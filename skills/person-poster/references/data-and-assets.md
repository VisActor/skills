# 数据口径与人物素材

## 可追溯的事实清单

数值比对与素材证据的可执行格式见 [来源证据与交付检查](evidence-checks.md)。先用capture_source.py保存实际原始响应，再声明定位并通过poster_workflow.py data显式生成字段，使用 `verify_evidence.py` 逐字段/整组比较，正式交付统一经过 `poster_workflow.py verify`；工具不替代源页阅读。

在 `data.json` 为事实和系列保留稳定 id、值、单位、统计范围、截止日期或所属时期、来源 URL/用户文件位置、舍入/估计限定。可将共用范围放在系列或全局层，不必为每个值重复整段元数据。派生值记录输入与计算方式。

例：球员的“常规赛总得分”和“季后赛总得分”属于不同统计范围；歌手的“Hot 100 冠军单曲”和“Dance Club Songs 冠军记录”属于不同榜单。数值相近或都叫冠军不能合并。来源使用当时可访问的原始统计机构、联盟、唱片公司、官方人物档案等；引用二次转载时保留原始出处与转述关系。

历史截止日期是叙事选择；查验日期不是数据覆盖日期。明确“截至2024年”后，不能将之后发生的记录塞进同一组。用户要“最新”或“生涯至今”时必须重新查证，不能复用姚明/麦当娜的静态事实。

全局统计范围来自资料明确给出的覆盖范围。发行、获奖、首秀或最后一条里程碑的日期属于对应事件，不能据此推导所有数值的统一截止日。来源只给生涯阶段或年份范围时，保留该范围；精确的 `asOf` 需要独立依据。核对最终HTML时也检查生成者新增的截止日、总计或“首次/最高”等限定，不只核对原资料中已有的大数字。

来源冲突先比较范围、更新日期和定义。不能解决时改选可证实指标，或展示有说明的范围/约数；不任意选一个精确值。实践中的提名口径冲突不应变成禁止所有人物使用提名数据的规则。

每项事实或共用同一口径的系列关联具体来源及其支持的范围。搜索过官方页面不等于已在该页找到全部指标；混用官方、第三方和用户输入时分别标注，不在 manifest 或图中笼统写“全部官方统计”。仅有搜索摘要、跳转代理或无法读取的原页面时记录缺口；可改用有证据的说法、替换指标或保留待核对，不能补一个机构首页作为逐项证据。

## 排版前核对事实到标签

数值正确不代表展示标签成立。在 `fact-review.json` 简短记录关键事实 id、展示说法、所依据的原文/数据、范围和核对结论，优先检查会改变标题、人物叙事或主要图表的事实。可按组核对，不为普通标点生成冗长审计表。一次查得的原始证据保存后复用，避免为了每个模块重复检索相同事实。

文件必须是可解析的非空 JSON 对象，不能将 Markdown 内容保存为 `.json`。可按实际证据使用以下结构；`pending` 不是通过，检查结果和来源内容由执行者填写：

```json
{
  "status": "pending",
  "checks": [{
    "factIds": ["career-series"],
    "claim": "当前页面使用的指标、值与范围",
    "source": "data.json 中该系列关联的真实来源 URL 或用户输入文件位置",
    "observed": null,
    "status": "pending",
    "limitations": ["尚未读取该来源的对应数据"]
  }]
}
```

新建作品按capture→data→`poster_workflow.py facts`先核查，再build展示；用户要求官方数据时保留实际官方原表/原文与查验时间。常规赛/季后赛、个人/球队、赛季/系列赛口径分别记录；来源有差异先解释选择，不通过改写摘录消除差异。

每项核对要匹配来源的**指标名称＋值＋时间＋统计范围**，而非只有一个机构域名或数字。最终回看HTML实际短标签：榜单、获奖/提名、单场/全程、独唱/所有艺人等类别必须与来源相同。当前纪录需确认截止日期仍成立；历史纪录用当时口径表达。未得到支持的次级数字可以删去，不能在验收记录省略该数字后将整页标为事实通过。

可编辑交付的 `data.json` 中未上图的字段也属于交付事实，不能保留未核对的填充值。百分比和场均值优先用来源的原始分子/分母复算并记录舍入位数；零分母保留不适用。发现一处抄录误差后核对同组所有行，保留原始摘录与修正记录，不只改被指出的单个数字。

批量系列先把来源的对应表格行保存为本地证据，再转换为交付数据，避免凭记忆补齐。逐字段比较实际交付值与源表，记录已核对数、未核对数及差异；有源文件和数据文件时用本地脚本比对，不用一句“官方数据已确认”代替。覆盖包括未上图的附加字段；不需要的未核实字段应删除。场均、百分比先核对该列定义；只有来源明确对应的总量与场次才可复算，不能将不同统计范围相除。源表已舍入时按相同精度比较，精确总量冲突单独说明。

- **年龄：**区分拍摄、播出、获奖或报道时年龄；记录采用的事件日期与周岁/虚岁/来源自述口径。有准确生日和事件日期才计算确定周岁；只有年份时保留范围或写明按年份差估算，不拼接不同基准的年龄曲线。
- **首次、最高、终身等限定：**写清“哪个范围内”。某部电视剧首次走红不自动等于职业生涯第一次演主角。决定纪念性质的逝世等事实先确认可靠发布及日期，再确定主题。
- **组成与派生标签：**总计减去已知类别只证明剩余数量；默认称“其他/其余”，除非来源另有明确分类。不能从角色大小推断有无台词，也不能从未获奖推断未提名。
- **记录数、人数与场次：**核对分母、计数对象、时间跨度及是否重复计数；把“选取案例”与“完整系列”区分清楚。

未解决的歧义先换为可靠说法或标明限定，不让漂亮排版固化不成立的标签。语义核对由生成者依据实际来源完成，静态校验器不凭关键词猜测某个人物的史实。

## 决定信息由谁表达

| 信息关系 | 主要载体 | 保留的语义 |
| --- | --- | --- |
| 单一人物事实、某次最高、独立荣誉次数 | HTML 数字与短标签，可配图标 | 指标名、单位、范围 |
| 赛季/年代等数值系列 | VChart 柱图/折线图 或适合的图表 | 时间缺口、零值与无数据区分 |
| 巡演/作品/球队等分类比较 | VChart 横条/柱图 | 完整类别、排序与单位 |
| 明确分子/分母的组成或命中率 | VChart pie 等组成图 | 分母、类别和互补关系 |
| 只有日期与事件的生涯节点 | HTML 事件轴/沿人物轮廓的短注 | 日期为标签，不是柱长 |
| 人物服装、姿势、情境和质感 | 人物素材/背景 | 不承担精确文字或数据编码 |

一个独立百分比不必为了补足100%强制加圆环；需要组成对比或用户明确要求时再图表化。不要为填满版面把无关指标画成同一组比较，也不要把完整系列拆成手绘 CSS/SVG 条形。

带年龄的若干代表作首先是事件节点。只有比较“这些事件发生在多大年龄”本身有明确分析价值、基准统一时，才以年龄作数值轴；表达等待、跨度与晚年突破时，优先用事件轴附年龄/间隔标注，避免把随时间自然增长的年龄当成表现提升。

每组精确数据有主要展示位置，图表已经包含的类别/数值不再完整抄到别的模块。允许提取一个有意义的核心总数、差值或极值作为强调，清楚区分总计与组成。图表样式改变不能改动数据、排序或轴起点来追求好看。

## 优先选择真实人物图片

优先使用用户提供或明确选定的合适图片；没有合适素材时，先搜索真实人物照片或可追溯的历史图像。官方人物档案、球队/机构、作品或活动发布页、注明出处的媒体原图是候选来源。搜索缩略图只用于发现候选，进入来源页核对人物身份、角色、拍摄时期与场景，再取得可用分辨率的原图。搜索和文件获取使用宿主实际可用能力，遵循其访问与下载限制，不绑定工具或其他 skill。

在数据定稿、下载和精确排版前打开候选的素材说明页，确认具体使用依据及可满足的署名/链接/改动条件；公开分享用途优先从依据明确的候选中选择。只有媒体信用署名、聚合页或未知条款时继续寻找；仍找不到则明确保留发布限制，不标素材通过。

按身份正确、主题/时期契合、脸部清晰、分辨率足够、轮廓可排版来选择，不仅看姿势是否接近参考图。候选只有壁纸/图片聚合页且不能追溯原始图注时，继续选有可核实出处的素材，不把文件名当作身份或年代证据。先适配可靠素材，再定精确布局：缺全身照可以用半身、胸像或偏置构图；背景不透明可以抠图或整合原有色面。姿态不同、需要透明背景或希望视觉统一，都不构成默认重造人物面孔的理由。裁剪、抠图及色调处理保留人物脸部、身体和实际动作，视觉统一主要由字体、配色、图标与版式完成。

抠图与保留照片是两条有不同验收条件的路线，按 [素材准备](subject-preparation.md) 明确选择。构图依赖人物剪影或用户要求抠图时，必须得到实际去除背景的素材，不能因只会裁边/渐隐而自动回退为矩形照片。矩形照片仅用于有意保留照片背景的设计；真实照片优先不意味着降低人物与数据整体融合的要求。

在 manifest 记录来源页面、原图 URL（可取得时）、本地原图、原始尺寸及实际处理步骤；摄影者/机构署名和使用说明按来源提供的内容记录，不猜测。下载与身份核实是不同步骤，工具成功不证明照片中人物或年代正确。搜索能力不可用或候选不足时，记录具体缺口，继续利用现有可靠素材；确实缺人物素材则明确交付草稿，不自动改用 AI 肖像或伪造完成。

用于分享或公开展示的网络素材，另记录来源页提供的署名、使用条款及条款链接/依据，说明裁剪、抠图等改动。找不到使用依据时写“未知”，保留发布限制或换用依据明确的素材；“新闻图片”“仅演示”“非商业”都不能代替来源许可。原页失效或下载成功仅能证明取得了文件，不能证明身份和使用依据已核实。不要把此记录扩写成对所有用途的法律保证。

## 用户明确要求 AI 人物插画时

用户明确要求 AI 插画/重绘时，使用可用的图像生成或编辑能力并遵循其说明，记录生成/编辑来源。真实图片作为参考时仍保留出处；AI 重绘结果标为生成素材，不称为历史照片。AI 可按需用于纹理等非人物素材，不改变人物照片的来源类型。

先用大致构图给素材提出约束，再按实际结果定布局。prompt 应包含：

- 人物身份与时期、可辨识的脸部/发型特征；资料不足时先确定形象依据。
- 姿态、面部朝向、手的方向、器具的位置，以及希望形成负空间的区域。
- 与主题一致的服装、主色与材质；人物肤色保持自然。
- 全身或明确的裁切边界；完整手、器具、头发与鞋周围保留余量。
- 目标媒介与真实 alpha 透明背景（需要抠图时）；只生成视觉素材，不生成姓名、数字、标签、徽标、图表或整张信息图。

原图有透明度且需编辑时保留透明度；不把轮廓测量脚本当作抠图或修图工具。生成不可用时说明未完成项，或使用符合用户要求的已有素材，不把浏览器截图/自绘形状声称为生图人物。

## 检查 alpha 与占位

需要透明素材时先按 [人物素材准备](subject-preparation.md) 运行 `prepare_subject.py`。它统一透明检查、工具无关的结果接收、保守裁边与最终几何；不会把不透明白底自动变成剪影。以下只读工具用于进一步测量最终素材，不承担抠图。

预览工具可能用黑底展示零 alpha 区域，也可能让带 alpha 通道的图片看起来像真正抠图。要同时查看图像和读取透明度。运行：

```bash
python3 "$SKILL_DIR/scripts/inspect_subject.py" \
  --image "$BUNDLE/assets/subject.png" \
  --bands 16 --alpha-threshold 128 \
  --place 220 295 820 1230 \
  --output "$BUNDLE/subject-geometry.json"
```

这些坐标仅演示 CLI；实际值取自当前作品的图像元素。工具以原图未旋转、居中 `object-fit: contain` 为模型，不支持 `cover`、旋转、额外 transform、偏置 `object-position` 或额外 border/padding。使用其他方式展示时需用浏览器实测对应的渲染几何。

报告里的 `occupiedBands` 是每个高度带中达到阈值像素的保守外接范围，透明空隙可能被合并，不代表所有范围内像素都不透明。`canvasBounds` 映射到海报 CSS 坐标；柔和发丝/边缘可能低于阈值，排版仍需留间距。脚本不识别人脸/手/器具，不会证明文字没有语义遮挡。

全透明或阈值过高导致没有主体时命令失败；RGB 或全不透明图片会被如实报告为矩形，不会自动移除背景。后者仍可用于色面构图，不应冒充透明剪影。

### 缺失事实和公开素材的交付边界

未观测、未出赛、不适用在原始数据中保留 null/缺失原因，绘图按 [柱图缺口示例](chart-types/column.md) 保留分类和缺口；不补0、极小正数或插值来填满版面。图表派生值的变化须能追溯到事实，不能让验收记录以“隐藏了”代替对实际标签的核对。

公开展示需优先选择来源明确给出可复用条件的素材，并按条件保留署名、条款链接和改动说明。只有媒体署名或“编辑用途”描述却没有具体使用依据时，usage 状态为 unknown，交付说明明确公开发布尚受限；这不等同于事实身份核对失败，但不能把整包称为已获授权或可直接公开。

每张位图的manifest写`usageStatus`与实际`usageTerms`；unknown/restricted阻止正式交付，acceptance不能覆盖。当前用途有具体依据且所列条件已满足才写verified，并保存本地原文；旧稿缺字段可诊断，正式通过前须真实复核。用户指定官方/原始数据来源时保留该约束，无法取得就说明阻塞并请求允许替代，不能自行换成第三方后称事实要求已完成。
