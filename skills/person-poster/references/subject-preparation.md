# 工具无关的人物抠图流程

人物素材优先来自用户图片或搜索核实的真实图片。照片不透明是正常输入，需要剪影时移除背景并保留人物原貌，不因缺透明背景而重新生成人物。所有图片都必须检查实际 alpha。包内 `scripts/prepare_subject.py` 沉淀的是可验证的文件流程，不内置特定抠图服务、模型、CLI 或另一个 skill。它支持任何提供本地透明图片的能力，也能直接复用已透明的原图。

先在简报确定实际人物呈现方式：`cutout`（人物轮廓跨背景/色面/数据区）或 `photo`（有意保留完整照片及其背景）。用户要求抠图、参考强调无背景人物或当前构图依赖剪影时，采用 `cutout`。此时不透明图片是待处理输入，不能把处理失败静默改成矩形照片。

独立 skill 不等于内置背景分割模型。本脚本不执行语义抠图；调用方必须用宿主实际可用的背景移除/图像编辑能力，按其说明保留人物、姿态和器具。没有能力时优先寻找身份/来源可核实的现成透明人物素材；仍不能满足剪影需求则继续资料和布局草稿，明确素材处理未完成，不将其作为最终通过的剪影海报交付。不要求固定服务或另一个 skill。

路线由空间关系决定：人物跨越色面、分隔线或图形是剪影路线；赛场互动、舞台环境等场景本身是证据时，可保留照片并让摄影边界参与构图。仅因底色相近或抠图困难而选混合模式，不是摄影叙事。

## 可选的本机能力与通用mask接口

任意分割能力可返回透明PNG，也可返回与原图**像素尺寸和方向完全一致**的灰度PNG：白色保留、黑色移除、灰色为部分透明。后者通过原始RGB应用alpha，不重绘、不自动缩放，不改变肤色。生成者先查看原图确认身份，选对前景实例后执行：

```bash
python3 "$SKILL_DIR/scripts/prepare_subject.py" \
  --image "$BUNDLE/assets/original.jpg" --mask "$BUNDLE/assets/mask.png" \
  --output "$BUNDLE/assets/subject.png"
```

在已有macOS14+及Swift的宿主，可直接使用包内的**可选**系统适配，无需下载模型或调用固定服务：

```bash
swift "$SKILL_DIR/scripts/macos_foreground.swift" \
  "$BUNDLE/assets/original.jpg" "$BUNDLE/assets/segmentation"
```

输出各前景实例的mask及`segmentation.json`。实例编号不是人物身份；查看候选，选择真正的人物及需要的器具，再用`--mask`接收。系统自动分割也可能漏发丝、球拍或麦克风，仍需原图/实际底色验收。其他平台或该能力失败时，使用宿主已有分割能力交回相同文件即可；本包不要求安装Swift，不把系统支持当成跨平台保证。输出目录可以不存在或为空；已有文件时换一个新目录，保留先前结果。

适配器同时接受常规两个参数和启动器通过 `--` 分隔后转发的两个参数；分隔符之前的启动器参数不作为图片路径。图片或输出目录恰好名为 `--` 时，使用绝对路径或 `./--` 避免与分隔符混淆。

若 Swift 报动态库加载失败或工具链不可用，这是启动环境错误，尚未执行 Vision 分割。优先使用宿主支持的完整工具链或其他已可用分割能力；不要猜测并永久设置 `DYLD_LIBRARY_PATH`，也不要删掉前次输出来反复尝试。保留完整标准输出、错误输出和 Swift 进程的真实退出码；`swift ... | head` 后的 `$?` 通常属于 `head`，不能证明 Swift 成功。先把命令输出重定向到任务日志、立即记录退出码，再查看日志。

## 阶段一：检查并准备

```bash
python3 "$SKILL_DIR/scripts/prepare_subject.py" \
  --image "$BUNDLE/assets/subject-original.png" \
  --output "$BUNDLE/assets/subject.png" \
  --crop tight --padding 16
```

- 返回 **0 / `prepared`**：通过基础 alpha 格式检查，完成 PNG 输出、裁边和几何报告；`cutoutAcceptance` 仍为 pending，按报告 `nextAction` 查看真实背景是否已去除。只有已确认是正确剪影时才无需继续抠图。
- 返回 **2 / `needs-background-removal`**：尚未生成可用人物文件。读取 `.asset.json` 中的 `nextAction`，选择当前宿主已有的图像编辑/分割能力，完成背景移除并保存本地结果。此状态是工作流交接，不是假成功或程序异常。
- 返回 **1**：文件错误、结果不透明、主体为空或准备失败；根据报告修复，不能带病继续排版。

仅存在 alpha 通道不够：完全不透明 RGBA、全局低透明度、白色背景、全透明图片都不能冒充有效人物剪影。默认要求至少1%像素为真正零 alpha，且存在达到128阈值的前景；这是可调的基础格式门槛，不证明抠图视觉质量。

灰色/白色矩形照片加透明边框或局部渐隐，也可能通过这个门槛。不要用 `prepared`、零alpha比例、geometry输出或后端成功作为“抠图成功”的结论。CSS渐隐、`mask-image`、混合模式和淡化边缘可用于已经正确的素材融入版面，不能替代背景分割。

## 阶段二：接收任意工具的结果

```bash
python3 "$SKILL_DIR/scripts/prepare_subject.py" \
  --image "$BUNDLE/assets/subject-original.png" \
  --cutout "$BUNDLE/assets/subject-cutout-result.png" \
  --output "$BUNDLE/assets/subject.png" \
  --crop tight --padding 16
```

调用方完成实际抠图，脚本验证实际结果。不要让调用方反复搜索工具名称：已有可用能力就直接使用；能力不可用时保留交接状态并说明具体缺失。不要把简单的白色阈值删除当成人物抠图，白衣、牙齿、眼白与舞台高光会被误伤。

结果格式、下载参数、认证与费用属于所选能力的实际接口，本包不猜测这些参数。使用当前能力的真实说明，保留面部、姿势、手、头发、服装和器具；不同服务均通过同一个 `--cutout` 文件入口交回，不要求安装某个特定 skill。

先对照原图确认处理没有重绘身份、五官、姿态或服装细节。图像编辑服务返回的透明图若实质上重生成人物，不作为保真抠图结果；改用真实分割或核实过的透明素材。原照片本身的边界裁切和噪点，与处理新增的误删、色边分别记录，不为掩盖限制而默认补画。

## 输出与裁剪语义

- `subject.png`：验证后的透明 PNG，原图和提供的抠图结果始终保留。默认不覆盖既有输出；明确重做时使用 `--force`，仍不能覆盖输入。
- `subject.asset.json`：输入/候选/输出尺寸与哈希、alpha 检查、流程状态、裁剪偏移及真实处理来源。报告可以随两阶段更新。
- `subject.geometry.json`：**最终输出**的轮廓及分带占位，用于后续布局；文件名、尺寸不沿用裁剪前的版本。

`tight` 用所有非零 alpha 像素的外接框裁边，并添加透明 padding。裁剪不使用128阈值，避免剪掉淡发丝和抗锯齿边缘。`keep` 保持候选素材的完整画幅；这两种方式都不重画人物、不缩放图片、不执行语义背景分割。

需要布局坐标时追加 `--place LEFT TOP WIDTH HEIGHT`，或对最终 `subject.png` 再运行 `inspect_subject.py`。映射仍是无额外 transform 的居中 contain 模型。

## 人工验收与来源记录

先对照原图与准备结果，查看人物周围、肢体间隙和器具边缘的背景是否真正去除，再放到海报实际底色上查看。检查脸、手、发丝、服装白色部位、麦克风/篮球等器具，以及残留矩形、白边、阴影或被误删的部分。后台返回成功、PNG格式、alpha检查都不能替代这次查看；报告默认 `visualAcceptance` 与 `cutoutAcceptance` 为 pending，不自动改为通过。

在成品验收中记录实际查看的原图/结果文件、是否仍有背景、人物完整性及失败后的处理。随后核对 HTML 实际引用的 `src/currentSrc`，须指向已查看的准备结果；改了素材但仍引用原图/旧文件也不成立。素材验收通过后才按最终轮廓确定精确坐标。轮廓通道不对时先解决素材，不把矩形的几何报告当作人物轮廓排版。

manifest 保留人物最初的来源类型与出处：搜索图片记录来源页和原图 URL，用户图片记录用户来源；只有 AI 原图记录生成工具与 prompt。另记录背景处理的真实工具/来源、原始文件、候选结果和准备报告。抠图不改变原始来源类型，不能把搜索照片改记为 AI 生图。脚本的 `performedByThisScript: false` 指明语义抠图由外部能力完成；透明原图复用路径没有实际抠图步骤。
