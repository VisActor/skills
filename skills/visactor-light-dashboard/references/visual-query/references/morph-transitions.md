# VChart Morph 与更新策略

用于图型切换、动画缺失、过渡闪烁、旧布局残留及中间图形异常的排查。以下更新参数与引擎行为已在 **VChart 2.1.7** 验证；升级时核对实际加载版本的公开 API 与运行结果。具体时长、缓动和视觉风格由宿主决定，不把某一次调参固定成所有页面的默认值。

## 分清三层复用

| 层次                | 推荐策略                                               | 原因                                                                                             |
| ------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| VChart 实例         | 连续图表更新保留实例                                   | 每次 release / new 会失去跨图型过渡上下文；切到 VTable 等不同渲染器时才按生命周期替换            |
| 内部图表 / 系列模型 | DSL 图型改变时通过公开参数重建；单纯数据更新不强制重建 | 普通 / 并列条形图同属引擎 `bar`，饼 / 环图同属 `pie`；引擎顶层 type 未变不代表布局结构未变       |
| 图元 reuse          | 需要原生 morph 的动画更新优先使用 `reuse: false`       | 相同图元类型的一对一复用优先于 morph；矩形换向时普通属性补间可能遇到不兼容的 width / height 表达 |

只检查顶层 `type: bar` 或 `direction` 会漏掉双轴图：它的顶层是 `common`，柱系列位于 `series` 中。也不要为每个遇到问题的图型维护一条特例；对需要图型切换的宿主，采用统一更新策略，再验证其实际图型与数据规模。

## 公开更新参数，保持 Spec 原样

分析配置和编码归 VBI / VSeed，动画阶段默认值等通用生成能力归 VSeed；实例更新、排队、系统动效偏好和释放归宿主。通过 VSeed DSL 的 `animation.morph` 控制图型切换形变（内置深浅色主题默认开启，`false` 关闭且保留普通动画），自定义主题可通过对应图型的 `config.<chartType>.animation.morph` 改变默认值，图表的显式配置优先；缺省或 `undefined` 配置继承主题。不在生成后批量强开 spec / series 的阶段、改写图元身份或修改引擎私有方法。

下面片段放在宿主已有的串行更新流程内。`spec` 是 VSeed Builder 的原始构建结果；`motionAllowed` 由宿主动效策略与系统偏好决定，不能覆盖 DSL 显式关闭的动画或阶段。

```javascript
const nextMorph = nextSeed.animation?.morph !== false
await instance.updateSpec(
  spec,
  false, // 完整替换配置，不与旧 spec 强制合并。
  { morph: motionAllowed && nextMorph, ...(motionAllowed ? { reuse: false } : {}) },
  renderedChartType !== nextSeed.chartType || renderedMorph !== nextMorph ? { change: true, reMake: true } : undefined,
)
renderedChartType = nextSeed.chartType
renderedMorph = nextMorph
```

- `renderedChartType` 和 `renderedMorph` 属于当前实例，首次渲染成功后初始化，释放实例时清空；每次实际更新完成后记录，包括已被更新请求取代、但仍完成提交的那次更新。不能只用滞后的 UI 状态判断前一图型。
- 第四参数重建内部模型，仍保留同一个 VChart 实例与旧图元的 morph 上下文。只传 `reuse: false` 不能解决内部模型未重建造成的旧分组布局。
- VChart 在创建 mark 时记录 morph 资格。仅修改开关可能留下旧资格；开关变化时同样重建内部模型，验证关闭再开启后的第一次图型切换。
- 单纯数据变化时，VChart 可以继续使用普通属性补间，不一定产生路径 morph。不要为了得到 pathProxy 而强制重建每次数据更新。
- `morph: false` 只关闭 morph，不等于关闭所有普通动画。减少动态效果还需通过当前版本的公开实例 / DSL 动画配置关闭动画，并停止已有动画；若实例初始化选项不能动态改变，在该偏好变化时重建实例。

`updateSpec` 的 Promise 完成表示更新提交，不表示动画播放完毕。沿用请求版本号、串行更新与仅保留最新待处理请求的调度；不要用固定延时阻塞用户切换。卸载、空结果和跨渲染器切换仍须取消待处理工作、解除事件并释放资源，见 [组合与联动](composition.md#刷新订阅与生命周期)。

## 保留原生身份与能力边界

- 不给所有 series / mark 设置同一个 `morphKey`。它会合并原本不同的系列配对，双轴的柱、线、点可能失去边界。保留引擎生成的身份；确需自定义时，应依据稳定且互不冲突的实际系列语义设计并验收。
- 不把原始数据的“第一个维度”强行设为所有图元的元素 key。VSeed 会重塑维度、度量与颜色字段，应基于实际渲染 datum 理解身份。分类增删、空值和多维多指标都可能改变配对条件。
- `morph: true` 不能让所有 mark 自动支持 morph。动画整体开关、阶段配置、图元支持与元素匹配都参与判断。显式关闭阶段、零时长和已有特效应保留，缺省阶段支持由 VSeed 负责，不能由页面强行覆盖。
- 组合图中共享的柱系列可以 morph，新出现的折线仍可使用原生入场；线 / 面、层级图和竞赛图不能因其他图元通过就被宣称全部支持路径变形。不匹配或不支持的部分保留原生过渡，并说明实际验收范围。
- 检查实际加载的 VSeed 构建是否包含需要的默认动画能力。未发布改动不能用旧发布包代替；按交付约束使用对应本地构建或内嵌资源，避免源码已改而浏览器仍运行旧代码。

### 多维数据与退化图形

元素 key 的集合相等还不够：一个主维度下的多个细分可能被引擎按数组顺序配对。跨编码时，柱图轴字段与饼图颜色字段也不表示同一粒度。由 VSeed 在 `unfoldDimensions` 已有遍历中生成稳定的原始维度组合身份（`DimensionKey`），用字段名和值的元组编码，避免拼接符碰撞、空串和数值零被误当成无 key；保留原生 `dataKey` 和系列 / 图元 `morphKey`。多指标共享维度组时，仍需验证双轴的原生拆分 / 合并，不能未经验证把指标也加进 key，导致源、目标集合不再匹配。

动画管线只读取维度键和已有统计，不再遍历、复制数据。现有视觉通道随编码变化，不能单独替代完整维度身份。

验证真实数据中的零值和负值。VChart 2.1.7 会把部分饼图扇区压成零角度；随它加载的 VRender 1.1.0 在通用路径转换中可能把退化扇区展开成大圆。全正值小样本通过不能证明利润等含负值指标正常。对已复现的退化输入，由 VSeed 读取已有 `foldInfo.statistics.min` 选择安全的原生过渡，保留原始值、最终几何和显式动画配置；不要删数据、取绝对值或在模板里补丁路径。正常输入的 morph 应继续回归。

也要判断整个图形的拓扑：雷达图的点能 morph，不代表它的线和面也能。让大块热力单元飞向小点、同时独立展开雷达面，容易造成中间遮盖；默认的扇形组裁剪还会截断飞行中的单元。可在 VSeed 中隔离这类元素配对并协调原生淡入，明确记录替代行为，不能把淡入宣称为完整图形的路径 morph。用户显式指定的入场效果仍优先。

## 从源码定位，避免无效调参

在 VChart 2.1.7 中，可沿这些环节核对现象，升级后重新确认：

| 现象                                       | 排查入口与判断                                                                                                                         |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 同图元切换只有普通补间，换向时中间尺寸异常 | `compile/compiler.js::reuseOrMorphing` 的 reuse 优先级；检查是否实际进入 `prepareMorph`                                                |
| 关闭图元 reuse 后仍保留旧分组位置          | `core/vchart.js::_updateSpec / _reCompile` 的模型重建路径；比较更新终态与独立新建目标图                                                |
| 双轴配对错误、部分系列消失                 | `series/base/base-series.js::_createMark` 与 `compile/util.js::diffMarks`；排查共用 morph key                                          |
| mark 支持 morph 却没有路径                 | `animation/utils.js::shouldMarkDoMorph` 的阶段门槛，以及 `compile/morph.js` 的实际元素 key 集合匹配；该版本还会忽略零 / 空串等假值 key |
| 配置了 duration 却不符合预期               | `mark/base/base-mark.js::tryRunMorphing` 到实际路径动画的参数传递；该版本未完整传递部分 morph 配置，阶段时长不等于路径时长             |

源码诊断与帧采样可以读取内部结构，但生产代码不依赖这些私有字段或猴子补丁。不要用未经实际播放验证的 `morphAll`、duration 等选项掩盖配对或生命周期问题。

## 验收必须包含中间过程

先在旧实现复现失败，再用同一数据与流程验证修复。最终画面正确、updateSpec 成功、动画耗时大于零，都不能单独证明 morph 生效。

| 场景                                                     | 过程与终态要求                                                                                        |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 普通 / 并列 / 百分比柱条双向切换，条形图与双轴图双向切换 | 共享图元出现真实连续路径；组合图其他系列仍正常呈现                                                    |
| 普通与并列同方向切换、饼与环切换                         | 不因底层 type 相同跳过必要的模型重建；分组、尺寸、颜色与目标图一致                                    |
| 同图型数据更新                                           | 普通补间或原生 morph 都可；中间几何连续且终态正确。改变类别间的相对数值，避免整体倍增被自动轴缩放抵消 |
| 分类增删、多维多指标、筛选与主题变化                     | 合法保留原生进入 / 退出行为，无错误配对、丢失系列或旧图残留；不要求不匹配的元素强行 morph             |
| 快速连续切换与中途打断                                   | 最后一次配置生效，实例和系列身份正确，无异常、残留临时图元或未清理动画                                |
| morph 开关与重新开启                                     | 关闭时中间帧没有路径 morph，普通动画保留；重新开启恢复连续路径，序列化保留选择                        |
| 减少动态效果、空结果、卸载、切换渲染器                   | 减少动态效果时逐帧几何稳定；清空与释放后不再收到旧更新或动画回调                                      |

用 `requestAnimationFrame` 在实际动画窗口采样，至少检查三个不同的中间路径状态、坐标有限、图形持续可见，并保存早 / 中 / 后段截图。VChart / VRender 的一对一变形可观察 `pathProxy.commandList`；多对一变形可能在目标图元的 **shadow 子图元** 中运行，不能只看父图元就判定没有 morph。结束后检查临时路径及子图元清理。普通属性补间则采样真实几何变化，不强求 pathProxy。

终态另建一个相同尺寸、相同 DSL 与视觉配置、关闭动画的目标图，对照各系列可见图元的位置、形状、颜色和数量，同时确认原实例仍被复用。等待实际动画结束再比较，不能把 updateSpec 的 Promise 当成结束信号。保留真实 UI 操作验收，并检查控制台、快速切换、资源释放和原有交互；调试入口单独通过不能替代宿主体验。

安全淡入另设过程断言：没有异常路径、几何稳定、透明度在合法范围内连续变化，并检查截图中没有突然出现的大面积遮盖。不要因为“坐标有限、终态正确”就接受失真的中间轮廓；全正值、零 / 负值、两维一指标的真实数据应分开验收。
