# 分析设计、核心发现与决策依据

本篇负责从业务问题选择分析、组织证据并形成判断。[指标深入分析](metric-analysis/guide.md)负责探索交互与返回动线，[visual-query](visual-query/guide.md)负责查询和渲染。现有模板提供实现基座，新的分析按任务与数据条件设计。

## 从问题与数据出发

- 明确使用者、当前要判断的问题及可采取的行动或核查。例如仓库负责人需要定位值得优先排查的履约组合；监测页也可以只回答当前状态是否值得关注。
- 确认事实粒度、唯一键、时间含义、单位、覆盖范围与可分析维度；区分实体快照、事件记录和聚合结果。比较前检查两组数据的范围和口径是否一致。
- 识别已有目标、历史或可比群体。缺少参照时描述分布与差异；缺少过程、成本或结果字段时，明确哪些解释和收益判断尚无证据。

这些是分析设计依据，按任务需要补齐，不要求用户填写固定表单。已有页面的小范围修改沿用已确认口径。

## 按问题组织证据

先选择能推进当前判断的方法，再确定图形。下表用于选型，不要求每页包含所有分析。

| 分析问题                                   | 数据条件与计算重点                                                   | 可采用的呈现                           |
| ------------------------------------------ | -------------------------------------------------------------------- | -------------------------------------- |
| 变化发生在哪里，哪些部分贡献较大？         | 有可比基期；贡献分解需明确可加总关系，多因素分解需交代方法和交互项。 | 两期对照、趋势、差异排行或瀑布图。     |
| 总体数字掩盖了什么差异？                   | 有记录级数据或有效分布统计；明确分箱、有效样本与异常判据。           | 直方图、箱线图、分位数或分布对照。     |
| 高数量来自业务规模还是较低效率？           | 同时具备规模、结果与有效分母，区分绝对数量和比率。                   | 规模与比率联合比较、散点图或并列指标。 |
| 结果是否集中在少数类别？                   | 类别与分母清楚；核对类别是否重叠，Top N 只限制展示。                 | 排行、累计贡献、结构图。               |
| 问题集中在哪些组合，可比条件下是否仍存在？ | 有交叉维度及足够样本；同时看样本量和比率，检查业务结构差异。         | 热力矩阵、分组对照、分层比较。         |
| 哪个步骤流失，哪些群体持续留存？           | 有真实事件顺序、实体键和时间窗口；阶段、去重与队列分母定义一致。     | 漏斗、路径或队列留存表。               |

每次深入应增加证据、缩小核查范围或暴露权衡。只更换分组、重复“最高 / 最低”或放大同一数字，通常不足以回答后续问题。

方法须有对应查询或计算能力支持。需要保存、重算或跨宿主复用的公式与依赖，按[派生计算与状态](visual-query/references/query-and-render.md)在所属 DSL 与 Builder 中建模；当前能力不足时说明所需的数据或计算支持。

## 从发现到下一步

结论按当前问题组织，必要时包含：

- **观察事实与证据：** 什么范围出现了多大的变化或差异，相比什么，涉及多少有效记录。结合影响规模与比率，避免仅因排名第一就判定最值得处理。
- **解释及边界：** 哪些关系已计算证实，哪些只是可能解释。检查样本量、分母、缺失和群体构成；差异较小或样本稀疏时，按方法适用性补充不确定性或敏感性检查。相关关系不能直接写成原因。
- **下一步：** 数据支持时指出优先核查对象、待验证假设与观察指标。行动优先级涉及成本、收益、可控性和约束；这些信息缺失时，给出核查路径。情景估算需写明假设，不能当作已兑现收益。

例如仓库履约问题，可先联合比较发运量、未按时率和未按时记录数，再看“仓库 × 运输方式”的组合分布，并在同种运输方式下比较仓库。已有数据仅含是否按时标记时，可以定位样本中的高影响组合；判断延误时长或具体环节，还需要承诺时间、到达时间及过程节点。这个例子说明证据如何推进，不预设哪个仓库存在问题。

## 计算口径与比较单位

基础聚合由 VBI → VQuery 执行，衍生指标消费同一范围的未格式化结果。具体分组、去重、周期及有效性规则见[数据形态与比较口径](metric-analysis/guide.md#数据形态与比较口径)。

- 比率先汇总再相除：利润率为总利润 / 总销售额，客单价为总销售额 / 区间去重订单数；不平均局部比率、不累加重叠分组去重数。
- 分母符合业务定义，零分母与无定义值显示 `—`；保留合法零值、负值及缺失语义，中间计算保留精度。
- 相对变化说明基数定义；负基期按指标语义确认比较方式。前期为零时保留本期值，并说明不可比。
- 比率从 10% 到 12% 为增加 2 个百分点；相对增幅才是 20%。增减是否改善取决于指标含义。
- 分布、比率和代表性按当前数据的采样与粒度解释。样本中的比例不自动代表总体发生率，缺失记录不能直接当作业务上的零。

## 结论、范围与证据

首页突出最值得关注的主要发现，证据围绕这一判断取舍，保留会改变结论的重要反例。当前范围、比较基准和必要限制就近可见；长公式与完整口径按需展开。文字长度由问题决定，不能机械复述全部卡片或为凑建议编造目标、阈值和原因。

筛选后重新计算发现与依据；局部 hover 保留为临时查看，不改写全局结论。探索后的发现对应当前选择，并能返回总体。布局与密度见[信息密度与模块取舍](layout.md#信息密度与模块取舍)。

## Insight 资源与联动

通过 `insight.setContent(content)` 保存内容，Dashboard 引用同一 Insight 资源。沿用所选模板的写入与解析协议，UI 用 `textContent` 与原生列表呈现；调整内容结构时同步解析。行序是页面协议，不是 VBI 领域定义。

Insight Builder 管理内容，不执行模型推理。需要 AI 总结时，调用方提供已计算的数值、公式、单位、范围、比较结果与有效性；保存结论文本不等于保存可重算公式。订阅、释放及资源快照见[组合指南](visual-query/references/composition.md)，交付检查见[验收标准](acceptance.md)。
