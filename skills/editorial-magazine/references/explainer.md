# 机制图解 · 观点与知识科普

从[四页机制图解模板](../assets/explainer.html)起稿。默认手机悦读版为 1080×1440，浅纸色、细网格图面、宋体问题标题和单栏解释；经典杂志版保留 1080×1920。整组固定图形、颜色和箭头的含义。模板中的扳手是可运行的排版示例，换题时连同图形、条件、图注和来源一起替换。

| 页 | 读者要弄懂什么 | 图怎么画 |
| --- | --- | --- |
| 问题封面 | 哪个现象值得解释？ | 放大主体或初始状态，留下一个具体问题。把完整因果过程留给内页。 |
| 结构或对照 | 哪些对象、变量或前提有关系？ | 剖面、局部放大或同尺度并列，标签贴近所指位置。在图下解释最关键的两处。 |
| 过程或论证 | 结果怎样一步步发生？ | 画出实际路径、阶段变化或论据与结论的联系。箭头区分顺序、流向和因果，正文按图的顺序读。 |
| 条件与应用 | 换一个条件，结论还成立吗？ | 用前后状态、反例或两种条件对照，回到封面的问题。区分尺度、适用范围和未知之处。 |

知识科普先核验机制，再画图。观点解读使用同一骨架，依次呈现议题、证据、推理与适用条件，清楚标出作者判断；相关性不能画成因果。页数按用户要求增减，超过一页的过程按语义拆分。用户要求保留原文时按原句和原序分配，图注另写。

每页原生 HTML 标题、一幅主图、一组简短解释和页脚来源。图随题目重画；部件用引线、变化用前后对照、数量比较明确单位和尺度。科学 SVG 标记 `data-image-policy="diagram"`，`data-image-reason` 写清解释对象，每幅有独立可读标签，重复图形定义的 ID 在全文内唯一。照片只有在能展示实际对象或提供证据时才使用，按[配图规则](imagery.md)处理。足以说明机制的原生图解可以独立承担主图。

手机悦读版每页保留一个问题或结论、一幅主图和最多两段解释。图内标签只保留读图所需的对象、方向、数值和单位；背景材料、例外条件与来源说明分别放在后续页和页脚，避免在主图周围堆满小字。

复制模板后保留 `article[data-page]` 和首个封面角色。制作时让箭头、图文、页码和页脚关系直接对应，再用[导出流程](export.md)生成逐页 PNG、ZIP 与 HTML。参考实例的知识依据为 [OpenStax 高中物理实验手册 · Levers](https://assets.openstax.org/oscms-prodcms/media/documents/STUDENT_HS_Physics_Lab_Manual_Full.pdf)；正式作品在来源清单写入本题依据。
