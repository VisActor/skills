# 正式配图与宿主生图

当模板需要摄影、拼贴或插画，而用户素材不足时读取本页。摄影或插画的 SVG 占位只表示构图位置；机制图解模板中的有标注示意图展示解释方法，随题目重画；生成了 HTML、SVG 或 PNG 文件，不代表配图已经完成。

## 先确定每幅图表达什么

**故事、新闻资讯的内容配图默认必须是实际获取的照片或生图工具产出的插画。不要用代码手绘 SVG、CSS 图形、Canvas/Pillow 几何画、图标或 emoji 补图片位，也不能把这些图转成 PNG 规避要求。** 页码、分隔线等小装饰不受此限制；用户明确要求示意图，或内容确实需要事实支持的图表时，才采用有解释作用的矢量图，不能以“主题示意”作为缺照片的通用降级理由。

## 原文无图与原文保留要求

原文没有内容图片，或只有头像、表情、界面图标，表示需要补充素材，不表示可以省略图文模板的图片。不要拿无关头像填图槽。先为各页列出图片用途，再主动调用宿主联网搜索并取得可用文件，不把“原文没图”作为纯文字成品的交付理由。

“尽量使用原文”“不要改写”“不要自我发挥”约束正文及事实表达，默认仍可检索相关配图；不改正文，把“资料图／情境配图／非当事人现场”与来源写在独立图注中。只有明确要求纯文字、不配图、仅用所给素材或禁止联网时，才按该项限制调整素材路径；不能自行推定用户禁止配图。禁止联网也不自动授权生成图片。

按以下顺序处理缺图：用户内容图 → 联网检索相关照片 → 无合适检索素材且用户允许时调用生图 → 仍不可用则明确交付待补图草稿。新闻优先现场或主体／场所资料图；叙事专题优先正文已有的场景、动作和物件，作为情境配图，不要求找到故事当事人的照片。多篇独立故事不借配图暗示同一人物或同一现场。搜索使用公开、通用的场景词，不把内部原文或匿名身份信息整段发到外部搜索。

缺图草稿保留图位用途，列明已尝试的关键词／来源、获取失败原因及缺失图位；未实际搜索不能声称“没有可用相关图片”。原文长时调整图文分配或续页，不能用“保留原文”作为删掉整组图片的理由。用户限制使搜图不适用时，记录该限制，不虚构搜索记录。

## 缺图时主动联网找图

没有用户素材时，先调用宿主图片搜索或网页检索工具，不停留在“可以搜索”的建议。先从正文提取可见对象与场景，而不是抽象情绪词：新闻用事件／主体／地点＋官方或原报道，故事用正文已有的地点、动作与物件查找情境配图。优先官方新闻室、原报道与可核验的摄影来源；首批结果不相关时调整关键词或来源，不拿无关图凑数。

打开候选来源页核对图像与说明，取得宿主允许获取的实际图片文件，确认能解码、尺寸适合图槽、无明显水印遮挡并记录来源及使用条件。搜索结果页、网页地址、无法访问的防盗链 URL 和缩略图截图不是已经准备好的素材。工具禁止下载或来源限制使用时，换可用来源，不绕过限制。

新闻优先事件照片，次选相关主体／地点的资料图并注明“资料图”；故事可用不指认当事人的场景／物件照片，并注明“情境配图”。不能把搜索到的陌生人照片描述成故事当事人。没有合适检索图或用户需要原创插画时，再执行下面的生图流程。检索和生图都不可用时如实保留缺图草稿，禁止自行画几个符号补齐。

按正文为需要的图槽确定主体、动作／场景、图注、横竖比例和素材类型，再准备图片。故事使用能承载情节的人物场景、叙事插画或摄影拼贴；概念科普依据内容选择实物照片、概念插画或可核验的机制示意。三联图分别表达不同细节、阶段或对照关系，不能只把同一装饰图换三个图注。

用户实际素材优先，其次是有出处的相关图片；需要原创场景、概念插画或拼贴而没有合适素材时，实际调用宿主生图能力。真实人物、事件与科学证据不能用生成图冒充；故事情境重现应标为插画／示意，不能假装是当事人现场照片。只要求摘取原文时，正文和引语不扩写，插画也不增添会被误认为原文事实的情节。

## 豆包办公：生图与抠图分开执行

- **新图生成**：发现并读取实际安装的创意设计／生图技能；提供 `doubao-creative-design` 时先读其入口与当前工具合同，再调用其图像生成能力。名称只作发现线索，不假设技能已安装，不编造调用命令、参数或执行成功记录。没有该技能时使用宿主确实暴露的其他生图工具。
- **提示内容**：按本次配图用途描述主体、场景、构图和留白，整组共享主题色与摄影／插画风格。只生成独立视觉素材，标题、图注与事实标签保留在 HTML 中，不生成整页带字海报。
- **结果落地**：等待工具完成，将实际返回的图片保存到本次作品素材目录，打开检查内容与清晰度，再替换模板图槽。临时链接先保存为可用文件，不能将提示词、任务编号或尚未完成的任务当作图片。
- **去背景加工**：需要透明拼贴时，取得原图后按[透明素材指导](cutouts.md)调用 MediaKit；已经合格的透明图直接复用。MediaKit 的去背景步骤不替代新图生成。

其他宿主按实际可用的图像生成工具及其说明执行，不依赖豆包技能。能力不可用或生成失败时，若有合适的用户／检索素材可改用并记录；否则交付明确标注待补图的草稿，列出缺失图槽与实际失败原因，不静默改成几何图标、占位人形或文字卡片后宣称成品。

## 配图绑定与来源

在 `sources.md` 中按页／图槽记录实际文件、用户来源／检索链接／生成工具、用途与图注；生成图简记提示内容，抠图记录原图到结果的对应关系，失败项保持待补状态。不要记录凭证或带密钥的临时 URL。

取得或生成素材时即完成图槽绑定：

- 每个保留的内容图槽均已替换正式素材；没有模板示例、未完成任务、破图、仅改图注的占位或重复凑数图。
- 图中主体、动作与正文／图注对应；裁切后仍能看懂，并满足版式所需的摄影、拼贴或叙事插画效果。
- **SVG 并非禁用**：有清晰标注、准确结构与解释作用的流程图、结构图和数据图可作为正式科普配图；纯装饰几何图不能顶替要求的场景插画或照片。不能仅凭扩展名判断是否合格。
- 科学机制、标注及数据单独核验；生成插画的视觉完整性不等于科学准确性。

新闻、时序故事与编辑拼贴模板的内容图片标记 `data-image-policy="raster"`。替换素材时保留标记；新加的内容图片也加上。`export.py` 会拒绝这些位置的 SVG、空图片或未替换的矢量占位；内联 SVG 改写也不能绕过。仅当用户明确要示意图或科普确需准确的解释图时，可将对应位置标为 `data-image-policy="diagram"`，并在来源中说明依据；不能为通过导出而改标记。小装饰不标为内容图。

导出器无法判断图意和来源，因此这些信息在素材进入 HTML 时一次性确定并记录；缺图草稿不得报告为配图完成。
