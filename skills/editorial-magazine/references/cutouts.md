# 透明素材：按宿主选择抠图能力

适用于穿搭全身与单品、人物肖像及辅图、明确要求独立抠图的旅行前景（默认风景封面使用渐变蒙版）。先完成素材加工，再进入 HTML 排版；透明度检查脚本不是抠图工具。

## 豆包办公：直接使用 MediaKit

在豆包办公中，需要移除背景时，**首选并直接使用内置 MediaKit 技能**，不要先尝试本地分割模型、安装 rembg 或用其他生图工具重绘，失败后才转向 MediaKit。

1. 发现并读取宿主实际安装的 MediaKit 图片技能（通常为 `byted-mediakit-image`），以及其要求的 shared 依赖和去背景操作说明。依照当前工具合同执行，不假定存在 `call_skill()`，不硬编码未经确认的命令、参数或鉴权方式。
2. 输入本次任务的原图，明确要保留的主体。人物／穿搭保持身份、姿势、衣服、鞋包及原色；建筑／山体保留可辨识结构、枝叶和孔洞。目标是移除背景，不能重新设计主体或用图标替代真实照片。
3. 等待实际处理完成，将返回的透明结果保存为本地 PNG。若返回临时链接，先下载并确认文件可打开；不要把临时链接直接当最终 HTML 的素材地址。记录原图与结果映射、实际使用的工具和处理情况，不在交付中保存凭证或带密钥的临时 URL。
4. 用下述检查及目视验收确认结果，再内嵌到 HTML。用户已提供合格透明素材时直接检查复用，不重复抠图。

### 人物全景页的执行与恢复

单幅肖像封面用原照裁切。为需要轮廓绕排的全景页选一张主体明确、脸部和肩线清楚的单人原照；先下载并解码，避免把搜索结果页、登录页、缩略图地址当原图。已有透明素材先检查，可直接复用。

豆包提供 MediaKit CLI 时先核对当前 remove-image-background 的 help/schema。常见 Cloud 合同为同步操作：

```sh
mediakit-cli image remove-image-background --image-url "$portrait_input" --scene human
```

按宿主支持的输入协议使用本地原图、可访问的图片直链或 tos 地址。默认输出 PNG。立即把成功响应中的输出 image_url 下载为 portrait.png；不要下载请求中的原图地址。先用下方检查脚本验证，再对照原照检查身份、头发、肩膀和残留背景。直接调用报错时按错误处理：链接失效换成已下载的输入，尺寸超限先等比缩小，鉴权或能力不可用时转可用后端，不原样重复请求。

若已有 NumPy、onnxruntime 和本地 U2Net 人像模型，可执行包内 CPU 后备脚本。模型由宿主提供，命令不会下载模型。成功会保留原图坐标并另存透明 PNG。

```sh
python scripts/remove_portrait_background.py --image original.jpg --model /path/to/u2net_human_seg.onnx --output portrait.png
python scripts/inspect_cutout.py --image portrait.png
```

在 sources.md 记录实际后端、输入、结果文件与校验状态。只有透明结果可用于 portrait_wrap.py。人物全景页须交付实际抠图。若处理失败，先换同一人物的清晰单人照片并用可用后端重试。仍失败时将此页标为待补抠图的草稿并说明原因；仅当用户指定普通照片布局时才改用独立图片栏。若用户明确要求透明文件，报告失败阶段及待补项。

## 其他宿主

按当前可用的图像编辑／去背景能力处理；在提供 ImageGen 的宿主，遵循其图像编辑规则，以原图输入并请求透明背景。不要假设豆包 MediaKit 在其他宿主也可用。人像可沿用上面的本地后备流程。

## 共用验收

```bash
python scripts/inspect_cutout.py --image /绝对路径/cutout.png
```

- 结果需同时有可见主体和实际透明背景；全透明、全不透明、白底及烘焙棋盘格都不合格。alpha 通道存在不代表边缘正确。
- 在浅色、深色底上对照原图，检查发丝、衣物边缘、包带、手脚、建筑轮廓及内部孔洞；主体不能明显缺失、改色或变形。
- `inspect_cutout.py` 只检查透明度并提供候选色；`portrait_wrap.py` 只从既有 alpha 轮廓计算绕排区域。两者都不移除背景。
- 本地保存实际透明 PNG，成品 HTML 内嵌该文件。素材记录区分已完成的处理与待补项；模板中的 SVG 占位仅展示图槽，不能作为真实抠图结果。
