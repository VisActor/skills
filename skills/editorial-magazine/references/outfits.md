# 穿搭组图：独立封面 → 多套总览 → 单套拆解

无论后续展示几套，封面先选一套最能代表主题的造型。封面用大字号时装刊头，完整造型居中，占据大部分高度。短主题和一句搭配提示分置人物两侧，避开面部、服装轮廓。根据照片裁去透明边距，完整保留头顶和鞋履，并为标题自然换行预留空间。

从 `assets/outfits.html` 复制封面和多套总览两页，`assets/outfit-detail.html` 做单套拆解。整组保留完整人物剪影、配色与简短解析，共用同一简洁中性背景；单品框用于解释搭配，不自动添加价格、品牌或购买入口。

## 组图编排

- 先从 outfits.html 取一张造型封面，保留头脚与服装原色。多套时封面后出总览，每页默认放2–3套，沿用现有大图短解析版式；再按同一顺序为每套生成一页拆解。例如3套通常共5页，4套可以为1页封面＋2页总览＋4页拆解，按实际内容和用户页数调整。
- 只有一套时用封面＋单套拆解，跳过多套总览，不复制相同人物凑总览；同套多角度合并，保留可用于单品辨认的细节。
- 总览与拆解共用 LOOK 编号、原图、服装颜色与素材映射。用户只要组合或只要拆解时遵循其范围。

## 先建立素材对应

用户提供实际穿搭照片时必须使用这些图，保持人物、服装款式、配色、图案、鞋包与配件对应；不拿参考版式中的模特替代。只有版式参考不等于提供了待分析的穿搭。多张照片若是同套造型不同角度，按一套处理，选主视图并保留有用细节。

未提供实际照片时，按用户主题获取来源清楚的搭配图，或使用宿主已提供的生图工具生成搭配示意，并明确是生成示意。若没有可用素材能力，先交可编辑草稿并说明缺图，不能把内置人形占位当完成。用户要分析自己的穿搭而未给图时需要其实际照片。

## 抠图流程

1. 查看原图，辨认要保留的人物、衣服、鞋包、帽子与手持搭配物。多人原图逐人处理，避免边界切错。
2. 按[透明素材与宿主路由](cutouts.md)处理：豆包办公直接使用内置 MediaKit，先读取其实际技能说明，再以原图输入获取透明 PNG；其他宿主按实际图像编辑能力执行。工具不可用时说明抠图缺口，保留原图与布局草稿，不静默换成矩形照片冒充抠图。
3. 提示词可从下面开始，按照片调整：

   > 仅移除背景，输出透明 PNG。完整保留指定人物、姿势、脸、发丝、衣服轮廓、花纹、原有颜色、鞋子、包和搭配配件。保留胳膊与身体、腿部之间应透明的空隙。不要重画服装、修身、美颜或更换人物；不要添加地面、阴影、文字、边框或其他人物。原图被裁切的部位保持裁切，不凭空补全。

4. 查看透明结果与原图。检查发丝、手指、鞋底、透明／半透明衣物、白衣与背景接壤处；确认没有残留大块背景、白底、棋盘格像素或被删除的包带。需要修复时仅针对缺陷编辑，不连续重新设计人物。
5. 对 PNG 做 alpha 检查，随后在浅色及深色底上目视检查。拥有 alpha 通道不等于抠图质量合格。原图缺少下半身时使用半身构图，不能把补画的鞋裤作为用户原本穿搭。

```bash
python scripts/inspect_cutout.py --image /路径/cutout.png
# 可选：只从衣服所在矩形采样，坐标为原图像素，避免皮肤/背景影响配色
python scripts/inspect_cutout.py --image /路径/cutout.png --region 100,180,600,900
```

脚本仅读像素并输出透明检查与近似候选色，不修改原图、不自动识别衣服；最终配色须与衣服目视核对。全不透明或全透明结果不能作为合格抠图继续。保留原图和编辑后 PNG 及对应记录，最终 HTML 使用 PNG data URI。

## 多套组合：布局与文字

穿搭默认以大幅完整造型为主，搭配色板与一小段解析。沿用模板较大的图片区域和易读正文；每套约40–90字可作为短解析起点，按实际内容调整，不为提高信息密度扩写成长文；单品信息放在后续拆解页，不挤占总览人物区。

手机悦读版的三套总览每套只保留一句穿搭思路和一段约 30–50 字的解析，三列人物使用同一可见高度与独立固定图框。文字自然换行只改变下方文字区，不能改变人物图框大小。更长的版型、材质、单品和场合说明进入对应拆解页。

默认三套三列、两套两列，每一套自上向下阅读：一句穿搭思路 → 人物抠图 → 3–5个配色圆点及色名 → 小标题 → 解析。人物等高视觉对齐、脚底统一基线，各列留足间距；完整造型用 `contain`，不为了填满槽裁掉鞋帽。用 CSS 多方向浅色 `drop-shadow` 做细贴纸边，不向上游要求在透明图中画背景或文字。

3:4 手机总览保留标题位置，把整组造型放低。按标题与页脚的实际高度分配中间区域，列间共享人物、色板、标题和正文的行高。短解析排在页脚上方，脚底与色板相邻。将同页全身透明 PNG 按列顺序传给 `python scripts/align_outfit_cutouts.py --output overview-assets look1.png look2.png look3.png`（套数随页调整）。把输出的 look-01.png 等依次嵌入总览，保留脚本补齐的透明边。脚本按可见轮廓统一人物高度并居中放进同尺寸画布，手袋或宽裙摆仍完整。各列标题共用至少两行的高度，单行居中，两行自然换行。总览中以脚底中央为基点缩到九成，让相邻造型之间留出空隙；最后一段与页脚使用固定版面间距，剩余高度优先分给人物区，不在页脚上方积出大块空白。

一套用拆解版，两套时总览两列，三套以上分总览页。三列保持人物大图、脚底与色板对齐，文字只讲清最有用的搭配要点。用户明确需要深入解析时再扩展文字或增加续页，不默认压缩人物图来容纳长段落。气泡是可选短观点，不能挤占人物空间或重复下面全文。

配色来自对应衣物：基础色、辅助色、点缀色，圆点大小可以等大，不把它们表述为精确面积比例。加色名使相近颜色仍能分辨，禁止随机色板。文字至少讲清配色关系与一项可见的层次／轮廓／材质视觉效果，有必要时再给一句替换建议；没有依据时不推断品牌和价格。


## 单套拆解：中央全身，两侧单品

中央是同套穿搭的大幅完整抠图，两侧是身上衣物和配件的独立图，底部保留色板与一小段搭配逻辑。参考图中的搜索框、网页导航、名人名字、品牌和价格不是模板要求，实际内容不沿用。

3:4 手机拆解页先给页首、底部配色解析和页脚留出文字实高，余下高度全部分给造型与单品。五处细节齐全时，人物占中间两列，上下两行保留全身，两侧放短说明与三处细节；最后两处细节在下方各占半幅，便于看清包形、鞋尖或裤脚。单品图和全身图按原比例 contain，图注随内容换行。解析与页脚之间沿用一行版面间距。只有2–3件可辨单品时减少框数、扩大留白；内容多时加细节续页，不能为塞满框而发明配件。

每个框包含单品图＋名称＋一句作用（约10–25字）；底部解析保持约40–90字。不要扩为密集长文，也不要让商品框比中央造型更抢眼。名字按照片可见特征写，例如“米白宽松衬衫”，不能仅凭外观认定材质成分、品牌、型号和价格。

### 单品素材依据

1. 用户提供对应单品图时优先使用，核对颜色、款式与造型一致。获取产品图时核实是否同款并记录来源；相似款必须标明，不能冒充原款。
2. 只有穿搭照片时，用该照片作为编辑输入，逐件提取可见衣物／配件为透明 PNG；检查图案、领口、长度、五金和颜色。抠图工具与 alpha 检查沿用上文。中央全身图与单品图保留同一原图映射。
3. 人体遮挡或折叠处不能直接证明完整商品形状。优先展示真实可见局部并标“局部细节”；若为说明搭配而生成完整平铺重建，显著标“单品示意，遮挡处为推测”，在来源记录写明。不得把生成补全当成原款商品实拍。无法辨认时不展示该项，不为贴近参考强行补六件。
4. 图像编辑提示明确“仅分离指定单品，透明背景，保持可见颜色、花纹与轮廓，不添加文字、品牌、配件或背景”，并逐件复核与全身造型一致。图案错位、换款、明显改色需修正；不能只凭透明通道就验收。

## 整组背景：随机一次、全页一致

制作素材和排版前选择背景。用户指定或续改已有作品时直接沿用；新作品默认使用：

```bash
python scripts/choose_theme.py --style outfits
# 重现同组背景
python scripts/choose_theme.py --style outfits --seed 123
```

候选为米白、燕麦、浅石灰、亚麻、粉笔白、灰米色，随机附带纯色或极淡细网格。这里“随机生成背景”优先由 CSS 生成，无需另做一张背景图片。将返回的 paper / ink / accent / onAccent / outline / panel / rule 写入同名 CSS 变量（onAccent 对应 --on-accent）；backgroundImage / backgroundSize 写入 --outfit-bg-image / --outfit-bg-size。所有组合页和拆解页复用同一组变量，不能只改其中一个模板的底色。HTML 不运行随机脚本，记录 seed、实际色值与纹理；重新导出或增页不重抽。

背景不能改变实际衣物色板。白衣靠轻微贴纸边或柔和阴影分离；先查看全部造型，若轮廓不足则统一调整全组背景／描边，不能单独换某一页。正文保持深灰色，框线淡且细。需要生成纸张纹理时只生成一次无文字、无物体、低对比的背景素材，所有页引用同一资产、缩放和位置，并记录来源；避免高饱和渐变、花纹与大噪点。

整组共用同一背景、纹理、字号和页边距；LOOK 编号、组合页与拆解页的全身图沿用同一素材映射，所有单品保留可追溯依据。随 HTML、PNG 与 sources.md 保存全身／单品素材映射及推测说明。内置矢量只是版式说明，不能作为真实穿搭成品交付。
