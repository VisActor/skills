# MBB 制图规范

MBB 是 presentation policy，不是新图表协议。先确定数据/来源、模板和映射，能力校验后再应用。本规范分“必须遵守的结构规则”“当前代码提供的 preset”“逐图表策略”。

## 默认适用范围

所有新建图表默认执行本文件的全部非配色规则，无需在 prompt 中写“MBB”。包括信息层级、明确的主标题、必要次级说明和字体、轴标题与网格、单位精度、标签与图例、排序比较、条件性标注、来源及逐图型策略；不是只套用图例或主题名。配色从现有内置候选池选择：原生/default、shared/base、McKinsey、BCG绿、Bain。模型可按表达需要主动选择，无需用户出现MBB或品牌关键词；无可靠选择依据时继承图表助手/宿主原生色。候选名称仅用于识别已有配色，不宣称咨询公司的官方背书。

用户明确样式高于默认规则；编辑已有图表或导入已有图表配置时，保留未要求修改的样式和布局。没有可证实的业务结论时使用清楚的主题标题，不编造洞察。新建时必须扫描数据并按 [自动洞察与标注](auto-insights.md) 先执行表达增量检查，再选择有必要的标注；已有表达充分时即使存在重要发现也可不加。四象限、强调最大值、排序与聚合仍按各自业务条件决定。

## 1. 不变量

默认不得改变：原始数据、统计口径、URL/source config、live/snapshot、图表类型、mappingSpec、已有业务语义。若规范建议换图、聚合、排序或 Top N 会改变解释，先提出并取得确认。

## 2. 信息层级

一张报告图按以下顺序阅读：

1. 结论标题：完整判断，不写“XX 分析/趋势图”。实际／预算、当期／上年同期等基准比较优先按[稳定主题标题](business/recipes/baseline-comparison.md#稳定主题标题)表达期间、指标与比较主题，当前数值结论由动态标注表达；用户显式静态标题按该配方的例外处理。
2. 必要次级说明：指标、时间、范围、单位、基准；在图表助手中与主标题放在同一个 rich title，不使用 `subtext`。
3. 主图：只承载支持结论的编码。
4. 直接标签/重点标注：标关键值、差距、拐点，不标所有值。
5. 来源脚注：来源、截止时间、样本量、定义、舍入/估算说明。

默认按 [富文本标题](model-spec.md#mbb-富文本标题) 生成单个左对齐 rich title，使用其中的字体层级与配置。次级说明仅在有必要补充的信息时生成，缺少信息时省略该行；按 [表达增量检查](auto-insights.md#表达增量检查所有图型通用) 去重。不依赖 theme 自动补齐文本层级或字号，`fontFamily` 继承宿主。用户指定主标题时保留原文，仅对默认呈现和事实性次级说明补齐；副说明可以描述已知时间、指标或比较口径，不能编造单位、数据来源、样本量或结论。

新建默认富标题的颜色按已确认的实际背景选择，具体前景与结构以 [富文本标题](model-spec.md#mbb-富文本标题) 为单源：`#0F172A`／`#64748B` 仅为浅背景示例；已确认 `clarity-dark` 实际背景为 `#202226` 时，默认主／次标题使用 `#F8FAFC`／`#CBD5E1`。其他背景按实际宿主可读前景处理；背景未知不猜主题、不声称完成适配。用户显式配色和已有标题保持，切主题不能自动全局重置；样式保留与图面可读分别核对，不把写入主题名或颜色规则当作模型、宿主或市场验收。

通用结论标题模板：`[对象] + [发生了什么] + [幅度/差距] + [时间/范围]`，适用于用户要求的结论表达。基准比较默认使用稳定主题，例如“2026 H1 核心市场与二线市场收入预算与实际”，不把当前计算值复制到标题。无法从数据证明的因果词、预测确定性和价值判断禁止写入。

## 3. 布局

- 结论标题左对齐，单一 title；不要用多个装饰性标题元素争夺层级。
- 绘图区最大化，减少空白；轴标题、图例和注释不得遮挡数据。
- 新建图表需要离散图例时默认置于绘图区下方并居中对齐，避免与富标题、最高刻度和首条网格线争夺顶部空间。使用 `orient:"bottom"`、`position:"middle"` 和 16px 顶部留白；旧宿主或显式 DSL 在 `legend-discrete.spec` 写 `padding:[16,0,0,0]`。不要用 `x/y/offset` 模拟位置，也不要误改只控制图例项彼此距离的 `item.spaceRow/spaceCol`。用户明确要求其他位置、已有业务布局或图例被直接标签替代时按实际意图处理。
- 保持信息层级和布局一致；轴标题、刻度、图例项及普通数据标签的字体字号由图表助手主题提供，省略新增fontSize/fontFamily等文字样式覆盖，保留模板位置。用户明确字号优先，不能以另一组硬编码字号替代主题继承。正文卡片以静态首屏可读为设计目标，不依赖 hover 才理解。
- 图例能被线尾/条末直接标签替代时隐藏；系列多或空间不足时保留简洁图例。
- 3D、阴影、过度圆角、装饰背景、渐变和动画只有业务编码作用时才使用。

## 4. 轴、网格和单位

- 柱/条形图数值轴默认从 0 开始；若截断，必须明确显示断轴并说明，不得制造夸大差异。
- 折线图可不从 0 开始，但必须保留刻度与范围上下文；多个图比较时轴域一致。
- 有值轴时显式显示可解释的指标标题：单指标用指标名，多指标同口径可用“数值”，百分比轴可用“占比”；连续 scatter 两轴分别解释其指标。单位已知才放入轴标题、次级说明或标签格式，未知不补造；没有轴的图型不新增轴。
- 同一轴的标题和刻度不重复单位。标题已明确单位时，按 [轴单位去重](data-and-formatting.md#轴标题与刻度的单位去重) 仅清除刻度的重复单位，保留数值缩放、普通标签与 Tooltip 格式。
- 网格线用 `rule`/低对比色，只保留帮助估读的主网格；不同时显示冗余 domain line、tick 和网格。
- x 轴有多层分组时，默认只展示最外层标签；在实际 x 轴显式设置 `showAllGroupLayers:false`，避免模板默认展开全部层级。只控制标签显示，保留完整分组与映射；用户明确要求多层标签时优先遵从。见 [x 轴多层分组标签](model-spec.md#x-轴多层分组标签)。
- 双轴两侧颜色与系列一致，单位清楚；缩放不得制造虚假同步走势。
- 百分比图明确 0–100%，百分点写 `ppt`/`pp`，增长百分比与份额变化不可混用。

## 5. 排序和比较

- 排名类 bar/horizontalBar 默认按明确的主要指标降序；时间按真实先后，流程、瀑布和固定业务序列按语义顺序。具体总量/系列/差距口径、并列/缺失处理和来源执行边界统一见 [排序规则](data-and-formatting.md#5-排序规则)，默认设计不覆盖 direct-live 限制。
- 同一组图固定系列顺序、颜色、轴范围和单位。
- 实际 vs 预算/去年：实际用 focus，基准用 context/灰；差异可用 marker，但不重复标值。
- 类别太多时建议 Top N + Other；只有获得用户确认后才聚合。

## 6. 标签和注释

- 标签显示决策所需精度；金额/数量使用一致缩写，百分比统一小数位。
- 多系列线图/面积图用图例或末端系列名表达身份。已有完整图例且用户未要求末端名称时，显式关闭实际 series 的 `seriesLabel`；普通 `label.visible:false` 只关闭数值标签，不会关闭系列名。保留用户明确需要的双重标识，不改模板默认值。
- 常规 label 用于值；seriesLabel 用于系列身份；totalLabel 用于有信息增量的合计。普通堆叠图只有一个有效层时关闭 totalLabel，避免与 label 重复。单指标 `waterfall/waterfallDecrease` 的普通 label 与 totalLabel 默认可能同时显示同一增量/总计值：每柱只需一个值时，在实际系列的 modelSpec 中保留 `label.visible:true`、显式设 `totalLabel.visible:false`；只改 formatConfig 或关闭 seriesLabel 不会去掉这份重复。用户明确要求两种不同口径时可分别保留并说明；保留源 e 总计标记与累计语义。单系列身份已明确时通常也关闭 seriesLabel。
- 避免同一值在轴、label、marker 和 tooltip 中静态重复。
- marker 文本短且有结论，标注线落在真实数据或明确阈值上。
- 来源必须有真实 URL 才展示。来源名可作为 rich title 的次级行，但可点击入口由 `source.pageUrl` 提供；无 URL 时不展示“用户上传 CSV/文件名”。截止时间、口径、舍入和样本说明可以放在 rich title 次级行，但不要冒充来源。

### 6.1 什么时候必须考虑标注

新建图表或整体分析/优化时，按 [自动洞察与标注](auto-insights.md) 扫描事实并执行表达增量检查；用户显式要求的标注按要求执行。自动同步后无法稳定定位或已知会严重遮挡时，说明限制，不能以装饰性标注替代。

### 6.2 标注类型决策

按 [发现与标注映射](auto-insights.md#3-把发现映射为现有标注) 选择比较、事件、阈值或区域表达，再按 [语义锚点](semantic-marker-anchors.md) 核对合法 target、模板与来源边界。`growth-line` 不用于 Mekko；时间事件须可映射到轴且不暗示未经证明的因果；scatter 关系与象限按下节处理，waterfall 净变化避免与首尾直接标签重复。

### 6.3 差异格式选择

- `value`：金额、数量等同单位指标的有符号差。
- `abs`：只关心差距大小且方向已由标题/色义表达。
- `percentage`：相对增长 `(end-start)/start`；start=0 时禁止。
- 百分点差、本层原值/归一占比差及旧格式兼容，统一按 [差异内容契约](semantic-marker-anchors.md#3-差异from--to) 选择；不能把累计边界当作本层数值。
- `CAGR` 按 [年度声明与计算条件](semantic-marker-anchors.md#31-年度字段声明) 生成；缺少年份或条件不满足时说明缺口，不替换成普通增长率。

新建差异填写业务 target，可与 commonOption 一次生成，坐标和 series identity 由运行时内部解析；不把先物化设为模型生成门禁。

### 6.4 Scatter/气泡图：相关性还是四象限

四象限不是相关性散点图的默认升级，而是把两个连续指标按阈值转成四类行动组合。按分析问题选择：

| 用户真正要回答的问题 | 推荐表达 | 必要条件 |
| --- | --- | --- |
| 两个变量是否同向、反向或近似无线性关系 | scatter/bubble；可选 `trendLine` | x/y 为连续数值，样本足够，拟合方法可说明 |
| 哪些对象属于不同策略组合、优先级或风险区 | scatter/bubble + 单个 `marker.quadrant` | x/y 各有一个有解释力的阈值，四个区域能对应行动含义 |
| 识别异常、聚类或局部模式 | 原始 scatter/bubble + 少量 point/直接标签 | 不用象限掩盖聚类或非线性结构 |

四象限的阈值依据按优先级选择：业务目标/政策界限/风险线 → 外部基准 → 用户明确认可的数据统计基准。零值可用于增长、差异等天然以 0 为中点的指标。不得为了得到四块区域而静默使用均值、中位数或分位数；若用户批准统计阈值，标题或次级说明必须写明“按中位数/第 N 分位数划分”及计算范围。

仅要求说明区域策略时，将长解释写在紧邻图表的正文，并明确对应的两项阈值条件；图内保留阈值、气泡和产品标签。不自动把四段说明放进四角文本框。用户明确要求图内名称时遵循四角布局，但固定位置不保证避开气泡。

象限名称由轴语义和方向决定，不固定使用“明星/潜力/观察/调整”。只有 x、y 都是越高越好时，才可使用“高-高”等正向组合；成本、风险、响应时长等越低越好的轴必须反转业务解释。气泡大小只是第三指标，不能改变点所属象限，也不能把大气泡自动解释为更优。

四象限生成前必须完成以下检查：

1. 明确 x/y 字段、单位、方向和阈值来源。
2. 按原始数据尺度填写 quadrant.target.x/y 的字段与阈值，不换算绘图区百分比。
3. 区域样式写 highHigh/highLow/lowHigh/lowLow 业务槽位。运行时派生两条线与 polygon 关联，模型不生成 key/positions，也不混入旧 partitionArea。
4. 标题或次级说明解释阈值与区域含义，不发明区域 label/name 字段。
5. 只在语义规范支持的 standard scatter/bubble 单绘图区使用。固定业务阈值的位置随运行时轴域重算；这不提升来源本身的同步资格，也不代表均值/分位数会自动重算。

缺少业务阈值或来源/图型不支持时，说明缺项并提出普通 scatter/bubble 等替代。仅缺尚未物化的轴域不应拒绝语义四象限；旧自由几何的轴域与 polygon 要求只用于编辑已有配置。

## 7. 语义色

统一使用语义槽，不直接把品牌主色等同于好坏：

- `focus`（品牌 preset 中称 `brandFocus`）：当前结论重点。
- `compare`（品牌 preset 中称 `brandCompare`）：主要比较对象。
- `context`：背景/基准/其余系列。
- `favorable`：业务明确定义的正向。
- `unfavorable`：业务明确定义的负向。
- `warning`：风险、注意、阈值。
- `categorical`：无好坏含义的类别。
- `sequential`：从低到高。
- `diverging`：围绕明确中点的偏差。

这些名字是生成时的语义角色，不是新增 DSL 色值字段；最终写支持的 fill/stroke/color 等字段。原生 clarity-light 的 categorical 色板为 `#0A345E #18ADED #A6A7AD #1A82EB #74CEF4 #E1E2E4 #138ABE #76B4F3 #898A91 #0E688E`。以下是该主题的语义基线：

| 角色 | clarity-light 基线 | 解释 |
| --- | --- | --- |
| focus | `#0A345E` | 重点 |
| compare | `#18ADED` | 比较 |
| context | `#E1E2E4` | 背景与非重点 |
| favorable | `#1A82EB` | 已由业务定义的有利 |
| unfavorable | `#DC6B6B` | 不利语义补充色，并非原生 categorical 色 |
| warning | `#D97706` | 警示语义补充色，并非原生 categorical 色 |

宿主或用户已经提供 theme/palette 时，focus/compare 按其主色和比较色适配，context 与已有背景层级协调，不把 clarity-light 色值强刷到全部宿主。例如 iDA 有独立原生色板，应继续继承其主题色。无法确认宿主色值时保留主题继承，必要重点先用描边、透明度或明确文本，或明确选择已有内置配色。仅有明确重点、比较或业务好坏语义时增量使用上述角色，不为默认规则重涂所有图形。

红/绿语义必须结合业务和无障碍可读性；同时使用文本、符号或位置，不能只靠颜色。

### 7.1 单图形选择性强调

新建图表或整体优化时，先按 [表达增量检查](auto-insights.md#表达增量检查所有图型通用) 判断是否需要帮助定位关键对象；需要时主动使用局部强调，已有表达充分时保留现状。重点是**支撑结论的 datum 或系列**，不是机械选择最大值、最小值或最后一期。

- 先确定主结论及其对象，再生成样式：单对象突出1个mark；必要的双对象比较突出最多2个，并区分focus/compare。系列趋势是结论时强调对应系列，不能只给无关末点上色。没有可靠重点时维持均衡配色，不为满足规则编造结论。
- 默认优先使用可区分的fill/stroke颜色：重点用当前已知主题focus，比较对象用compare，其余用协调的低饱和context。没有已知主题色且允许选色时，可明确选择已有原生基线，例如重点深蓝 `#0A345E`、背景灰 `#E1E2E4`；这是一项主动配色选择，不宣称宿主自动提供这些颜色。不能因为“继承默认色”就让重点与背景完全相同。
- 如果已有分类色、瀑布方向色或用户固定色承载语义，保留其色义，以同色系明暗/饱和度、描边或线宽建立强弱层级。无法安全改色时才用opacity/texture等替代，并保证仍可读；不得为了高亮把扣减色换成增加色，或把多系列比较全部刷灰而丢失类别区分。
- 强调与标注分别判断必要性，不把“有结论”当作必须同时加色、加框、加文字的理由。用户明确要求突出对象时，以局部图形样式落实；补充说明仅在有表达增量时添加。
- 输出前必须检查：主结论对象是否命中、重点与背景是否有明确样式差异、强调范围是否过大。用户明确要求突出对象、或已决定用样式帮助定位却未形成可辨别变化时，视为未完成；若受用户明确配色/局部编辑范围、可靠定位能力或分类语义限制，应说明具体约束，不猜目标。
- “最高柱”只有在“最高”本身就是结论时才强调。若结论是Q2回落，则突出Q2而不是最高Q4；若讨论增速放缓，则定位支撑该比较的期间。
- 用户显式样式和局部编辑范围优先；不覆盖未授权的颜色。普通高亮不意味着业务好坏，不能把某个红/绿或品牌色固化为通用重点色。
- 排序、筛选、同步或换源后，新的分析/生成应重新判定重点；静态markStyle绑定业务对象，不是自动执行“当前最大值”的检测器，不承诺同步后自动重选重点。

落点：整组强调使用 `dataGroupSpec[groupKey]`；单个柱、点、扇区、节点或单元使用 `markStyle[]`。一般情况下 `markStyle` 的 `seriesIndex/itemKeys/itemKeyMap` 必须来自当前物化/runtime picker。当前内置 standard parser 的“单维度 + 单指标 + 单 series `barGroup`”可按 element-editing 中声明的窄规则直接使用 `_editor_dimension_field + _editor_type_field`；其他结构仍需 readback，不能从数据数组位置猜单图元身份。

### 7.2 商务角色与填充

样式用于区分角色和已知区间，不替代数值、图例或业务口径。以下规则与前述色义共同适用；用户明确样式及已有编辑优先，不把角色名写成 DSL 字段。

| 角色／目的 | 默认表达 | 适用边界 |
| --- | --- | --- |
| 实际主值 | focus 实心填充 | 实心不自动表示有利，费用超支仍是实际 |
| 预算、上年、目标基准 | context 浅色；明确要求轮廓时用透明填充＋描边 | 保留基准名称，不把空心误读为缺失 |
| 已给定预测 | 折线按虚实线契约；柱面需要区分时可用稀疏斜线纹理 | 需要预测数据和截止点；不用纹理伪造置信区间 |
| 灰度打印、单色区分 | 明暗＋角色标签；必要时仅给基准或预测加一种纹理 | 不能只靠红绿；保留可读数值与图例 |
| 目标区间、阶段窗口 | `markArea.area.style` 低透明度底纹（例如 0.08） | 仅限已知范围，底纹置于数据后；不把区间当阴影装饰 |

填充图元支持的 `style` 使用 `fill/stroke/lineWidth/fillOpacity`，纹理用 `texture/textureColor/textureSize/texturePadding`，见 [样式字段](model-spec.md)。斜线可用 `bias-lr` 或 `bias-rl`。例如明确要求预算斜线时，为预算分组的 `bar.style` 写：

```json
{"fill":"#E1E2E4","stroke":"#898A91","lineWidth":1,"texture":"bias-lr","textureColor":"#898A91","textureSize":8,"texturePadding":4}
```

这是原生基线的候选参数，不是全部尺寸的可读性保证。纹理开启时尺寸为正、间距非负；关闭时按既有样式契约处理四字段。轮廓柱可以用 `fillOpacity:0` 配合可见 `stroke`，不关闭整个图元 `opacity`。整组样式通过 [语义分组 target](element-editing.md)写入，单点强调走单点通道。

不默认增加投影、立体效果、渐变或装饰背景。用户所说“阴影填充”若实际指斜线／网纹，用纹理表达；有会影响结果的歧义时明确区分投影与纹理。柱体样式和图例符号是两项配置，不能假定图例自动复现纹理；若符号只展示基色，必须保留明确角色文字，核对读者能否对应。

开发视觉验收同时检查角色一致、实心／轮廓／纹理可区分、底纹不遮值、无无依据装饰、文字层级、灰度、编辑保持及目标尺寸导出。配置中存在 texture 不代表图面或导出已通过；普通生成任务仍遵守 Skill 的执行边界。

## 9. DSL 落点

- 模型选定非原生内置候选时写layer `theme`与chart `attribute.theme`；commonOption对应根theme和`options.config.theme`。选择原生/default时省略新增主题覆盖以继承宿主，保留已有主题/显式颜色。
- 新图按所选候选和语义需要写chart `attribute.color`/`markStyle`（commonOption位于`options.config`）；已有图只有授权换配色或具体重点调整时增量修改，避免覆盖其他样式。
- 标题写入 `modelSpec` 的 title entry，结构见 [富文本标题](model-spec.md#mbb-富文本标题)。
- `modelSpec.axes/legends/series`：显式值轴标题visible/text、简洁网格及必要标签/图例。轴标题、刻度、图例项和普通数据标签省略新增文字样式覆盖，继承图表助手主题字体字号；用户明确要求字号时才在对应style写入，不生成无意义空style。需要series identity时仍按真实物化结果，不猜ID。
- `marker`：阈值、差距、异常或关键事件。
- 来源：仅在存在 URL 时使用 `source.sourceName + source.pageUrl`；不要重复创建来源 text 元素。其他必要口径可进入 rich title 次级行。

应用 preset 时保持 modelSpec/marker 其他字段；不可用只含色板的新 config 覆盖它们。

## 10. 逐图表策略

以下规则全部纳入默认决策，但按业务目标、数据语义和实际模板能力适用，不是无条件增加所有组件。不得借设计规范改变用户指定图型、过滤数据或覆盖模板标签位置（显式同色导致不可读时按 [标签可读性](labels.md#同色标签可读性) 窄例外处理）；需要此类改变时先提出建议并按用户授权执行。展示顺序按 [排序规则](data-and-formatting.md#5-排序规则) 处理，本地新图按明确业务顺序排列完整行不改变数据口径；来源和已有图表的限制仍优先。

- Bar：排名类按明确的主要指标降序，时间按真实先后、固定业务序列按语义顺序；主系列 focus、基准 context；结论由单个类别支撑时可用 markStyle 突出该柱，不机械突出最大柱，也不固定使用某一种颜色；堆叠只在总量有意义时使用；barLink 只在构成变化是结论时开启。
- Horizontal bar：选图未指定且长标签或排名是目标时优先考虑；普通值标签保留模板默认位置，只有用户明确要求条末或左对齐时才覆盖对应位置/对齐；显式要求条形和标签同色时按 [同色标签可读性](labels.md#同色标签可读性) 避免柱内同色。
- Line：有比较重点时最多突出1–2条；需直接标识系列且模板支持时用线尾seriesLabel；需点说明时优先起点/终点/拐点；有业务目标阈值才用marker目标线。
- Area：只在量级/累计重要时使用；透明度低，避免多层遮挡。
- Pie/Rose：适合少类别份额表达；类别多可建议条形图，但用户指定图型时不擅自改型；不得用面积制造夸大。
- Scatter：明确轴标题，单位已知才写、样本量可由实际数据确认；只有策略分群且两项业务阈值明确才标象限，有业务相关异常点才加说明；趋势线有分析依据且能力支持时使用并注明拟合方法。
- DualAxis：不同量纲必须解释；若结论依赖视觉相关性，优先拆图或标准化。
- Waterfall：普通单指标瀑布默认区分总计、增加、扣减三种方向色，按 [瀑布语义配色](waterfall-colors.md) 落配置；递减模板按扣减方向而非原始正负判断。业务好坏另行判断；保留贡献顺序和累计方式，结论依赖净变化时避免重复标值。
- Funnel：标阶段值与转化率，突出最大流失；阶段有严格先后。
- Sankey：结论明确时可弱化非重点路径；节点过多时建议筛选，只有用户接受数据范围变化才执行并说明。
- Mekko：明确宽度/高度定义，保留原生轴类型与类别标签机制，见 [Mekko 宽度与轴契约](data-and-formatting.md#mekko-宽度与轴契约)；需要强调时再调整局部样式。
- Heatmap：连续量用 sequential，有中点的偏差用 diverging；缺失值单独编码。
- Hierarchy：层深或节点过多时可建议收缩展示或筛选，保留完整数据，需改变范围先取得用户授权；业务重点路径/节点可高亮，精确排名可建议配bar/table。
- Gauge/WordCloud：报告中谨慎使用；无法满足精确比较目标时建议数字卡/条形图，不擅自替换用户指定图型。

## 11. 默认设计配置验收

- 标题可从数据验证，包含时间/范围。
- 数据、mapping、source 和 live/snapshot 与应用前一致。
- 所选配色属于内置候选池、具有表达依据且同组图稳定；无依据时原生回退。用户显式主题和既有编辑颜色保持，选定preset写在正确层级。
- 色义一致，重点不超过 1–2 个。
- 单图形重点与标题结论一致；视觉属性符合业务语义、主题和用户意图。
- 轴基线、单位、排序和精度合理。
- 标题符合 [富文本标题](model-spec.md#mbb-富文本标题) 的结构和字体层级；必要次级说明有事实依据且不重复已有表达。
- 值轴标题visible/text及内容明确；轴标题、刻度、图例项、普通数据标签未被默认固定字号或其他文字样式覆盖，继承图表助手主题，用户明确样式和模板位置保留。
- 必须逐项核对标题、次级说明、轴标题、字号、网格、标签、条件性标注和配色边界；仅检查 theme 名字和图例位置不能判定完整默认设计通过。
- 静态首屏无需 hover 即可理解是设计目标。
- 需要图例的新图默认配置为下方居中（bottom/middle）及顶部16px留白；用户指定位置和已有布局优先，不将配置检查声称为视觉无重叠验收。
- 已知的截止时间和必要口径明确；有真实来源 URL 才展示链接，未知信息不编造。
