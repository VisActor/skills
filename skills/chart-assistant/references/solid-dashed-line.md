# 虚实折线：同一指标的分段线型

用户要求“一段实线、一段虚线”“6—9月用虚线”或“实际与预测衔接”时使用内置 `line`。虚实是同一业务对象的分段样式，不是两个独立指标；只有用户或数据明确声明实际/预测、完成/计划时才使用这些名称。仅指定线型时用时间段说明，不推断未来数据一定是预测。

## 构造连续的两段

1. 先按 [时间与排序规则](data-and-formatting.md#5-排序规则) 确定时间顺序和来源边界，再确认虚线从哪一个相邻点间的线段开始。默认“6—9月用虚线”包括5月到6月的连接；用户明确“仅6月到9月之间”时，5月到6月仍为实线，共享接点改为6月。
2. 将一个指标拆为实线段、虚线段两列；各段范围之外填 `null`，保留原始值和真正的 0。在两列中重复同一时间、同一数值的交界点，用于连接，不新增观测、不纳入合计两次。数据本来就缺失时保留缺失，不插值或补零。
3. 映射 `x` 为时间列，`y` 为两段数值列。同一对象两段用同色、同线宽，实线 `line.style.lineDash:[0]`、虚线例如 `[8,6]`；点样式保持一致，接点避免两份重复数值标签。不要用普通 line 元素或标注线覆盖真实数据趋势。

用户案例的完整数据为：

| 月份 | 3—5月 | 6—9月 |
| --- | --- | --- |
| 3月 | 30 | null |
| 4月 | 25 | null |
| 5月 | 30 | 30 |
| 6月 | null | 27 |
| 7月 | null | 32 |
| 8月 | null | 35 |
| 9月 | null | 40 |

5月的第二个30只是连接锚点，所以该列仍叫“6—9月”。两段共享最后一个实线点，虚线才会从该点接到第一个虚线点。仅拆列而不重复交界点会断开；把段外 `null` 改为0会产生假跌落。

## 系列名与数值标签分别处理

单对象分段图默认关闭**所有实际 series 的 `seriesLabel`**，即使图例已经隐藏也要显式设置。可在富标题次级说明中写“6—9月使用虚线”，或已知含义时写“实线：实际；虚线：预测”。此时没有区分业务对象的需要，通常同时隐藏图例。普通数值 `label` 按读数需求单独决定。

`label.visible:false` 只关闭数值，`legend.visible:false` 只关闭图例，二者都不会关闭 `seriesLabel`。线模板默认启用系列标签；实线段提前结束时，末端系列名可能经长引导线对齐到绘图区末端，看起来像数据继续横向延伸。不要为去掉引线把实线段补齐到最后一个月。

关闭的 canonical 配置是每个实际 series 对应的 `modelSpec` entry：

```json
{ "seriesLabel": { "visible": false } }
```

将该片段深合并到实际 entry 的 `spec`，保留其 `id/specKey/specIndex` 和其他配置；不是新增 `options.config.seriesLabel`，也不是 `dataGroupSpec[groupKey].seriesLabel`。`seriesLabel.label.space:false` 只影响布局，不等于隐藏标签。

多个业务对象各拆两列：对象A两段同色，对象B使用另一色；默认同样关闭拆段产生的全部系列标签，用下方图例辨认对象和阶段，避免图例与线尾标签重复标识。用户明确要求线尾名称时保留要求，按 [单系列标签编辑](labels.md#3-series-label) 使用实际标签 key，只给需要的对象/阶段保留名称与引线；不能猜 `styleMap` key 或承诺存在按业务对象自动合并图例的开关。

## 图例符号也要区分虚实

保留实际/预测或实线/虚线图例项时，符号本身应显示连续短线与分段短线，颜色仍按业务对象一致。仅在名称中写“实际/预测”或增加次级说明，不能替代符号的线型编码。

默认 `roundLine` 是填充形状。即使预测线的 `lineDash` 已传到图例，当符号 `lineWidth:0` 时仍显示完整的短实线；只放大符号或重写折线 `lineDash` 不能解决。当前图例编辑契约提供 `shape.style.symbolType/size/fill`，使用自定义填充路径直接表达实线和虚线：

```json
{
  "solid": {
    "symbolType": "M -0.5 -0.05 H 0.5 V 0.05 H -0.5 Z",
    "size": 24
  },
  "dashed": {
    "symbolType": "M -0.5 -0.05 H -0.25 V 0.05 H -0.5 Z M -0.125 -0.05 H 0.125 V 0.05 H -0.125 Z M 0.25 -0.05 H 0.5 V 0.05 H 0.25 Z",
    "size": 24
  }
}
```

这是两种可复用 `shape.style` 片段，`solid/dashed` 不是DSL字段。为各项添加对应对象的 `fill`，按实际图例的 `modelSpec` identity 深合并到 `spec.item.styleMap[可视索引].shape.style`。索引是当前过滤后的零基图例项顺序，需先取得实际渲染项与业务名称的对应，不能使用系列名、series ID或图形ID；重排/分页/筛选/同步后复核命中。参见 [Legend item](element-editing.md#4-legend-item)。

示例的24用于让三段短线清晰可辨，可以按图面调整；保持各项一致的大小及原有文字样式、位置、选择状态。不要在图例里生成当前契约未声明的 `lineDash`、formatter函数或使用额外画布线元素伪装图例。`symbolType` 的自定义路径格式见 [VChart 官方符号文档](https://github.com/VisActor/VChart/blob/develop/docs/assets/option/en/graphic/symbol.md)，最终以目标运行时显示和保存结果为准。

## 身份、交付与来源边界

分组线型写入 `dataGroupSpec[实际groupKey].line`，系列标签写入实际 series 的 `modelSpec`。多列不一定对应多个 VChart series；从物化结果的 `dataGroupMap` 和实际 models 获取身份，不能把“两列”理解为 `series-0/series-1`。复用本会话已确认且结构未变的身份即可，无需重复物化。无法取得身份时交付数据构造及待合并配置，说明尚未完成样式命中，不声称虚实线和标签已经生效。

- [单对象完整示例](../examples/solid-dashed-line.json) 使用本案例数据及已核对的模板身份；只在相同模板、数据结构下复用，其他结构重新确定身份。
- [多对象两阶段示例](../examples/solid-dashed-line-multi-object.json) 展示两对象拆列、样式与模型合并；占位身份须由目标运行时返回值替换。
- 原始数据已按两列拆好时直接消费；本地数据/明确允许转换的快照可以执行上述拆列。`direct-live` Sheet 需要源表本身提供可直接消费的列，不能在模型侧拆列后仍承诺原 URL 自动同步。既有图编辑保留未要求改变的数据、来源及样式。

交付检查：虚线边界正确、同对象同色、段外空值保留、接点值相同、系列标签已按意图显式配置、时间语义未变；保留虚实图例时，各项符号也要区分线型。此检查不自动启动渲染；开发回归另查真实线段、引线、标签、图例符号及保存重开。教程来源：[图表制作 - 虚实折线图](https://bytedance.larkoffice.com/wiki/WJ3Hw9OvIi5Hu8kMtGgczmiFndc)。
