# 实际与基准比较

适用于实际／预算、当期／上年同期及同口径目标比较。输出既有 `commonOption`；编辑已有图先读取完整保存态，只改授权范围。可直接加载的[季度预算实例](../../../examples/business/baseline-comparison/common-option.json)使用合成收入数据，不把示例的单位、颜色或数值带入用户数据。

## 1. 先确定可以比较

识别类别、实际、基准、单位、期间及用户要标注的对象。字段名只帮助识别角色，不能证明单位与期间一致。检查每个类别×场景唯一；多维表保留完整业务键。

- 预算缺失：请求对应预算，不能把目标、上期或 0 当作预算。
- 缺失值不补零；只比较两端都有有限数值的对象，说明未完成的对象。
- 单位不同需要明确换算依据；全年和季度、累计和当期不直接相减。
- 重复键不静默求和或取第一行；确认分组维度或用户认可的汇总口径。
- 比例指标明确 0—1 或百分数尺度；总体比例需要分子分母或有效权重，不能平均各对象比率。
- 只给两期主值不能推导收入、成本等变化原因；可以完成独立授权的主值比较，归因部分保持待定。

对于 Sheet direct-live，不改变读取后的数据形状、不派生、不排序源数据；按[来源契约](../../sources-and-sync.md)选择可直接消费的模板。不支持时说明具体缺口，不能转换后仍声称自动同步。

## 2. 选择原生表达

默认 `barGroup`；长类别优先 `horizontalBarGroup`。预算与实际是同一业务的两个场景，不能相加堆叠。

明确要求参照柱在后时用 `overlapBar`／`overlapHorizontalBar`，`mappingSpec.overlapBaseline:"column"`，`y` 的首项为基准、第二项为实际；不得用 `sum` 把预算＋实际当整体。需要差异标注时仍核对当前模板支持，不因重叠图已出现就称标注成功。

用户指定 `dumbbell`、`bullet`、`smallMultiples` 时保留选型并核对能力；哑铃、小多图不支持差异类 marker，子弹图需真实目标与递增阈值，不能把普通图差异配置复制进去。无法满足显式标注要求时说明该部分限制，不静默丢弃。

## 3. 计算事实与动态标注

差额为 `实际 - 基准`；基准大于 0 时，差异率为 `差额 / 基准`。金额／数量合计先分别求和，再算差额和差异率，不平均分项差异率。负值本身不等于数据错误。

基准为 0 或负数时，本配方新建默认只表达差额，说明未使用普通差异率。使用层级差异且同时请求差额与差异率时，显式设置 `label.formatConfig.nonPositiveBaseline:"differenceOnly"`，并保留 `content:["layerValueDiff","layerGrowthRate"]`：运行时按当前真实基准决定输出，基准非正时仅显示差额，恢复正值后重新显示率；策略随保存重开和撤销／重做保留，不改写源数据或作者 content。

该策略支持上述成对内容，也允许只选 `layerValueDiff`：关闭差异率后保留差额和策略，再开启时继续按当前基准判断。不适用于只要求率、累计边界、占比、CAGR 或顶部总计括号；这些请求按各自口径检查，不静默替代。省略策略的旧图保持原公式与零分母诊断，不批量迁移。用户明确要求其他负基准公式时先确认含义，不强加此策略。它不提供自动业务方向切换或持续口径告警。

无参考图且未指定形态时，同类别预算／实际按层级差异生成：

```json
{
  "id": "q1-budget-difference",
  "name": "hierarchy-diff-line",
  "target": {
    "from": { "match": { "季度": "Q1" }, "metric": "预算", "boundary": "end" },
    "to": { "match": { "季度": "Q1" }, "metric": "实际", "boundary": "end" }
  },
  "label": {
    "visible": true,
    "formatConfig": {
      "content": ["layerValueDiff", "layerGrowthRate"],
      "nonPositiveBaseline": "differenceOnly",
      "fixed": 1,
      "separator": true
    }
  }
}
```

两端由基准指向实际，不随排序交换。显式顶部括号请求按[差异形态与内容](../../semantic-marker-anchors.md#按参考图判别差异类型)选 `total-diff-line` + `value/percentage`；不只改 marker 名却保留不合法的 `layer*`。不得写死 `label.text:"+20%"`。

百分点差用同一百分比指标的两个对象。例如 columns 为“场景、转化率”，预算 0.10、实际 0.12；转化率列声明 `dataFormat.dataType:"percent"`，两端 metric 均为“转化率”，match 分别为预算／实际。使用 `percentPointDiff` 得 +2 pp；相对增长为 +20%，不能混写。不同指标列的宽表不能直接假定满足同指标要求；如需转换，先满足数据来源及用户授权边界。

只给明确需要的对象加标注。合计事实可以在回复中说明，不默认画静态合计文本；回复和主题标题不会随用户后续改数自动更新。

## 4. 样式与业务方向

按 [MBB 商务角色与填充](../../mbb.md#72-商务角色与填充)区分实际和基准。默认实际 focus 实心，预算／上年 context；颜色表达角色，不自动表达业绩好坏。收入增加是否有利、费用降低是否有利，应由用户业务定义决定；方向未知只说“高于／低于”，不说“达成／超支”。

值轴含已知单位，底部居中图例。普通标签与轴字体、位置继承主题和模板。纹理只在明确要求、打印或单色区分有必要时启用，不默认铺满所有柱子。

指标为比例／百分比时保留原始数值（如 0.10、0.12），同时设置数据列显示格式和实际值轴 `modelSpec[].spec.label.formatConfig.dataType:"percent"`；列格式或 `percentPointDiff` marker 不会自动设置轴刻度格式。检查轴显示为 10%、12%，而非仅标签为百分比、轴仍显示 0.10、0.12。

### 稳定主题标题

本配方的新建图表默认以“已知期间＋指标＋比较主题”命名，例如“2026 年前三季度收入预算与实际”“2026 年 8 月转化率预算与实际”。期间未知时省略，不编造日期；只有 Q1 时可写“Q1 收入预算与实际”。标题与次级说明保持主题及口径，不默认写入当前差额、差异率、百分点、合计数值或随数值变化的高低／增长／下降结论。

标题不是数据绑定：当前计算结论可以在回复中说明；图内已授权的差额、差异率或百分点由动态 marker 表达。不得为了突出结论，把 marker 的当前计算值再复制到标题、次级说明或独立静态文本中。即使首次计算正确，这些文本也不会随编辑数据重算。

用户明确提供或要求带数值、方向结论的标题时，保留该要求；核对当前数据是否支持，并在回复中说明该标题为静态文本、改数后需手动更新。已有图只改授权范围，不因本默认规则重写用户标题。此规则限定本比较配方，不禁止其他任务按事实生成业务结论标题。

分组样式用 `dataGroupSpec:[{target:{measure:"预算"},value:...}]`；单对象用 `markStyle[].target.selector/measure`。Marker 用 `match/metric`，两种 target 不混用。语义样式首次物化后保存原生身份，不能把它描述为持续重放的业务规则。

## 5. 输出检查与编辑边界

1. 按 [工作流校验](../../workflow.md#commonoption-交付前校验)验证完整配置和默认样式；只出现主图不代表所有语义 target 已成功。
2. 核对原始值、配对、分母、单位、顺序与标注内容。示例 Q1 为 +20/+20%，总计为 +20/+5%；不是平均分项比率。检查标题、次级说明与独立文本是否符合[稳定主题标题](#稳定主题标题)，不能只检查 marker；显式数值标题例外须有用户要求及静态更新说明。
3. 说明缺失和未完成请求；不得以降级输出冒充全部成功。
4. 改数据后动态 marker 重算；排序不交换 from/to。字段重命名、删除、来源同步、样式身份迁移按真实运行时结果判断，失效绑定不得改绑到其他对象。
5. PNG 按完整内容边界导出，包含超出编辑区的标注与图例，因此可能大于原设定宽高；不据此承诺固定尺寸下自动避让。自动差额排序、自动有利色、静态文本更新和附表联动需分别核对；不把配置合法当作运行验收。

普通配置任务遵循 Skill 执行边界，不额外要求本地浏览器验收；写卡时执行 readback。业务配方的开发验证与模型首次生成评测分别记录，不将固定示例当作模型表现。
