# 多图共同快照与图表附表组合（开发宿主协议）

用户明确要求两张独立图共同排序、筛选或比较尺度时，先确认它们表达同一组类别与本地标准快照。不能仅凭列名相似就合并不同来源，也不能从“万元/元”等文字猜换算关系。图表助手可分别生成原生 `barGroup`、`horizontalBarGroup`、`line` 与可选 `ListTable`；关系本身由编辑器 UI 建立，**不是 commonOption 可直接注入的字段**。未确认开发宿主支持 `BusinessCompositionV2` 时，不承诺联动持续更新。

建立关系前明确：唯一类别键、各图使用的数值字段、共享单位、每张图到共享单位的正倍数与有限偏移（`canonical = local × factor + offset`）。至少两张图属于同一尺度组；需要不同尺度组时各组至少两张图。输入有重复类别、非数值度量、单位冲突、无限计算或来源仍在线同步时先澄清/拒绝，不能隐式聚合、补零或换算。

编辑器把原始 standard 数据和稳定行键保存在一个 `snapshot` 权威关系中。共同排序与等值筛选只改变各成员投影，原始数据及稳定行键不丢失；共享数值域由过滤后各图的数值换算到共同单位计算，再反算成每张图的本地轴域。图表和附表改一个原始单元格、增加/删除行列、可信字段改名、同 schema 快照替换、明确加和/差额/比值计算、成员度量绑定及 `barGroup`/`horizontalBarGroup`/`line` 切型都应通过关系命令执行并一起撤销。成员独立编辑或删改映射不可静默脱离。

计算只允许两个已存在原始数值字段的 `sum`、`difference`、`ratio`，除零拒绝；输出字段不覆盖原字段。删除被图、表、计算、排序或筛选引用的字段须先解除引用。整份快照替换必须保持明确的原始列 schema 与新的唯一稳定行键。开发编辑器的“复制完整组合”会复制全部成员并分配新元素/关系 ID，作为一个撤销单元；普通单成员复制仍拒绝，不能留下失联对象。

图表+附表首版可选宽屏并排或窄屏置下、附表最多每页12行。竖柱类别沿 X 轴、表格行沿 Y 轴，宽屏并排不具逐行像素对齐；窄屏置下以真实表格行高留足空间。PNG 导出当前画布/当前表页，CSV 导出全部权威行。多图 V2 的自动布局按当前画布尺寸安排全部成员；带附表时，若当前画布容不下所有可见行就拒绝布局，不能把裁切当成成功，也不把 V1 的附表分页冒称 V2 已支持。排序、分页、导出与当前页可见内容需分开核对。真实宿主、外部来源同步、发布仍属最后的独立验收。
