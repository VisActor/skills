# 目标与实际绩效页

用户要求单页经营绩效、目标与实际总览，并希望同时看趋势和对象明细时使用。按问题选择必要模块，不固定卡片或图表数量；只要求目标对比单图时使用[基准比较](baseline-comparison.md)，不扩展成整页。

若要求每个 KPI 自带全年趋势，见[带月度小图的指标卡](monthly-kpi.md)，按指标分别组织摘要与月图。

定位是 Agent 创建、用户可编辑的报告页。数据获取、清洗、聚合和指标计算由外部专业工具或调用方完成；本配方消费已处理数据，组织表达、编辑和交付，不要求统一明细格式，不新增共享数据引擎。原始输入例子用于说明口径，不表示图表助手承担把明细加工为全部组件结果。

## 数据与参照

先核对外部结果的期间、对象键、指标单位、可加和性与业务方向。月×地区明细需要完整组合键；季度目标、实际和上年同期须覆盖相同月份与对象范围。总体达成率和同比应来自总金额，不能平均各地区比率。以下公式用于核对已给定结果的含义：差额为实际−目标，达成率为实际÷目标，同比为实际÷上年同期−1；非正参照的处理沿用基准配方。结果缺失或口径不一致时交回数据工具补齐，不在图表助手中新建计算管线。比例指标总体仍需明确分子分母或有效权重。

达成率和同比回答不同问题：同比增长可以与目标未完成同时存在。仅有主值不能推导客户、价格或销量等原因。模拟数据须标明，不填虚假来源。Sheet direct-live 按[来源契约](../../sources-and-sync.md)处理，不能先聚合再宣称保留自动同步。

## 组合现有元素

| 阅读问题 | 现有表达 | 选择依据 |
| --- | --- | --- |
| 整体表现怎样 | 宿主已支持时使用原生 `kpiCard` | 每行一个已汇总指标；主值及已给定同比、完成率直接绑定字段 |
| 哪些对象偏离目标 | `horizontalBarGroup` / `barGroup` | 实际与目标为并列场景，不相加堆叠；差异标注只放必要对象 |
| 变化发生在哪段时间 | `line` | 月份保持时间顺序，目标、实际、同期的身份与颜色稳定 |
| 数值能否核对 | `ListTable` | 使用同一批快照生成对象明细，区分金额、比率与参照 |

原生 KPI 须与实际宿主核心能力匹配；Skill 能生成配置不证明宿主已部署。`mappingSpec` 的 `name/value` 绑定名称与主值，`key/unit/yoy/mom/completion/direction` 按需绑定已有字段；完成率以比例表示（0.9833 显示98.3%），方向1表示高好、−1表示低好。`yoy`、`completion` 不是计算公式，修改主值不会自动重算它们。本例把同比增长率和目标达成率各作为一张卡的主值，采用百分数值加单位（如 98.3 加 %）。若改绑定到 completion，需要使用比例值，并按阅读问题决定是否保留独立达成率卡。缺少原生 KPI 时可省略卡组或采用明确的固定快照文字，不把文字冒充绑定卡片。

组件已有标题时优先用组件原生标题，随组件移动、保存与编辑，不额外叠一个同义文本标题。标准数据表的原生标题当前属于完整编辑态 `attribute.title`；commonOption 的 `options.config` 不接受 `title`，table 的 `modelSpec` 也不负责把它转为表格标题。需要时先物化、读取真实表格，再只补 `attribute.title` 并保留其余保存态；不要为一次写入发明字段。可执行流程见[两阶段实例](../../../examples/business/performance-page/two-phase.json)，[原始输入](../../../examples/business/performance-page/input.json)为合成数据。

本例的宽表 line 系列身份在物化后确认，才用真实 `modelSpec` 关闭冗余系列标签、设置线型。换字段或改变数据形状时重新核对身份，不能把示例 series ID 当通用规则。KPI 换行会改变自身高度，普通多元素画布不自动把下方图表整体下推，需留足空间并检查完整表格行。

表格增加原生标题后，按真实标题高度与全部行高检查 `attribute.layout` 的内容高度；只增加外层 `rect.height` 不保证内部表格可视区变大。本例还在已物化表格设置六列的原生列宽，使明细与上方两图共用页宽。实例的 layout 坐标来自该表物化后的检查，仅适用于该版式；换数据或字号后重新测量，不能复用常量高度掩盖末行裁切。

## 快照与更新边界

本配方首先使用外部工具提供的口径一致快照。地区汇总、月份汇总、KPI 与明细在普通 commonOption 中各自保存数据；改单个图或卡，不会自动改其他元素。原生差异 marker 可以跟随其所在图的数据重算；固定文字、独立表格的派生列以及 KPI 已给定的同比/完成率不会因此重算。

用户调整颜色、字号、标题或位置时直接使用现有编辑能力。用户要求换一批数据时，由外部工具准备各组件的新结果，Agent 按下面流程更新；受限组合不是整页换数的前提。用户明确要求已支持的共同排序／筛选时，才按[受限组合协议](linked-charts.md)检查宿主。当前该关系不包含 `kpiCard`，其边界不构成本配方建设统一聚合引擎的理由。

## Agent 换数保留人工编辑

本配方在同模板、兼容字段的本地实验中，已验证保留组件配色、布局、字号和独立文本未修改片段的样式，保存重开后仍一致；这个范围不等于所有局部样式都能随任意数据变化继续生效。

**KPI 绑定数值的字符级样式是例外。** 用户对旧值的部分字符改色或改字号后，即使字段和业务键不变，主值由 `1180` 换成 `1280` 时，当前运行时也会因保存的源文字与新值不同而不再应用旧字符样式，退回部件基础样式，避免错套字符。保留 `richText` 配置不等于新值仍显示该样式。本配方不承诺自动迁移这类样式；涉及该情况时说明限制，用户要求保留此类样式或查看效果时再核对实际显示，未完成时不称保留成功。整段一致的颜色、字号可沿用已有部件样式能力，不据此新增字符迁移或数据处理逻辑。

1. 读取当前完整 record／`browserData`，沿当前 layerId、elementId 定位目标，保留原 record、元素身份、映射、手工 layout、modelSpec 及仍适用的局部样式，按上述范围判断可保留项。宿主可能在重开时重建layerId，不跨重开缓存旧身份。不得用初次生成的 commonOption 覆盖用户后续编辑，也不按元素数组下标定位；检查真实内部layout，不能只看外层rect。
2. 接收外部工具处理好的同批结果，核对列、类型、期间、单位和业务键。数据包须同时包含需要更新的 KPI 主值、已给定同比／完成率和表格派生列；不要只换主值。完整标准数据及其表格缓存必须一致，不拼接旧缓存和新行。
3. 同模板、兼容 schema 的开发宿主可复用现有 `data-change` 数据编辑入口；`data-replace` 的映射重建语义不适合直接套用。完整编辑态写回继续走宿主已有的读取／保存协议。缺少对应读写能力时只交付候选配置，不能把本地 Core 验证视为所有 Agent 宿主已可操作。
4. 核对与本次数据相关的期间、单位及结论文字，保留用户措辞和文字样式；颜色／线型等编码说明也应与当前人工样式一致，不沿用已失真的固定颜色名称。独立文本存在 `textConfig` 时它是实际显示内容，只改冗余 `text` 会留下旧文字；按真实富文本片段更新必要内容，保留其余片段样式。已有标注按[换数与结论核对](../../special-logic.md#3-数据更新替换和换源)处理。
5. 保存后回读，核对各组件数据、业务 target、人工配色与布局；要求查看效果时再核对真实图面。字段、分组值、类别集合或顺序变化时，额外核对组／单点／单元格覆盖，不把 `keepStyle:true` 作为身份仍有效的证明。KPI 绑定值的字符样式还需按上述例外核对，不能仅凭同 schema、同业务键或配置仍存在就认定保留成功。

已有入口逐元素更新可以完成一次成功批次，不等于整批原子提交、一次撤销、失败回滚或并发写保护。具体宿主未提供并验证这些语义时，明确更新范围及结果；不为本配方新增通用数据依赖或计算引擎。

按用户需要讲图：先看总体目标达成，再定位对象差距，最后看时间走势、回明细核对。说明可核实事实和下一步需要的数据，不把阅读提示固定成每页必备模块。交付前核对各汇总加总一致、总体比率的分母、标题归属和完整可见行；要求更新时分别验证单图重算、跨组件一致性及保存重开，不能互相替代。
