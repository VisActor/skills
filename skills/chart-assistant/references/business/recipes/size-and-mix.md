# 规模与结构 Mekko

用于同时比较组间规模和组内构成，复用 `mekkoPercent`：有效柱宽表达规模，段内高度表达构成占比。可直接加载的[规模与结构实例](../../../examples/business/size-and-mix/common-option.json)使用合成收入数据，已知单位万元；不把示例单位、期间或分类带入用户数据。不新增业务保存协议、表达式或规模推断算法。

## 1. 先核对规模与组成

每组需要唯一业务键、同口径规模与组成绝对值、单位和期间。优先输入组成绝对值；只有组成完整、互斥且与规模同口径时，才能将组成合计作为规模。来源独立给定的总量须逐组核对且每组只计一次，不能因长表每层重复总量而再次求和。

- A 的总量 100，食品 60、其他 40；B 的总量 60，食品 15、其他 45。总量分别等于组成合计。A/B 有效柱宽为 100:60，食品高度为 60%/25%，其他为 40%/75%。类别留白不参与宽度比；总规模为 160，不能重复累加每层的带宽。
- 等构成但规模不同的核对例：A 总量 100、食品 40、其他 60，B 总量 1,000、食品 400、其他 600。两组食品高度均为 40%，有效柱宽为 1:10，食品绝对量为 40/400；等高不能解释为等规模。
- 独立总量 A=120、组成仍为 60+40 时，保留原值，说明差额 `源总量 − 组成合计 = 20` 并先澄清遗漏项或口径；不静默改总量、缩放组成、虚构其他项或归一后称已一致。
- 只有占比时不能虚构各组规模或默认等宽后仍称 Mekko。缺少真实规模先请求补充；用户明确接受后才交付百分比堆叠替代，并说明它不表达组间规模。
- 总量为零时无有效柱宽，组内 0/0 构成未定义；保留源行并说明零规模不可显示，不静默删组。某个组成项为零而组总量为正时，该层占比为零，不补成非零面积。
- 负总量或负组成不适合本配方的非负规模／构成口径；保留原值并请求解释或另行选择图型。不取绝对值、截零或将正负抵消后继续展示正常组成。缺失项不补零，重复业务键不自动合并；不同单位、期间或构成不互斥先澄清。

## 2. 原生字段映射

实例保留一组一行的宽表，`columns:["大区","总量","食品","其他"]`，采用：

```json
{"x":"大区","y":["食品","其他"],"bandWidth":"总量"}
```

`bandWidth` 只进入宽度映射，不再放入 `y` 参与构成；`y` 保存绝对值，交由 `mekkoPercent` 计算每组构成，不能把占比另行乘规模后混用两种口径。组成顺序保持一致，类别默认保留源顺序；用户要求排序时对整行排序，组成、总量和业务键一起移动，不能独立排序带宽列。

静态 snapshot 实例的 `总量` 是独立数据列，没有公式绑定。只把 A 的食品 60 改为 80，组成变为 80+40，食品高度变为 2/3，但带宽仍为源总量 100；它不会自动变成 120，也不会自动生成口径告警。要保持组成与总量一致，应在确认当前业务口径后同时更新总量为 120，此时 A/B 有效柱宽才变为 120:60。每次生成或明确请求复核时重新核对源总量；不承诺编辑后自动更新回复、解释或来源事实。

长表转宽表、计算总量或聚合都属于物化转换。URL 输入按[来源与同步](../../sources-and-sync.md)判定 direct-live 资格；不能转换为静态数据后继续声称 direct-live 或自动同步。需要转换时明确 snapshot 及手动重建边界。

## 3. 稳定主题、标签与标注

按 [MBB 规范](../../mbb.md)继承字体、留白、已知单位及配色。默认标题使用已知期间、指标和规模／构成主题，如“各大区收入规模与构成”；标题及次级说明解释“宽度＝收入规模，高度＝组内构成占比”，不写死当前最大市场、份额或差异结论。期间未知时省略，用户明确要求静态结论标题时说明改数后需手动更新；已有图只改授权范围。

次级说明写入 rich 标题 `text[]` 的换行片段，继承 12px/18px 信息层级，不写被当前标题路径忽略的 `subtext`。组成使用跨组一致的系列颜色并显示食品／其他图例；本例食品突出、其他弱化，不把面积直接称为利润、增长或第三个独立指标。宽度和高度单位分别说明，不能将占比列格式误用于组成绝对值。使用原生百分比标签，类别标签可显示 `dimension/value` 表达组名和规模；不在百分比段顶端写“100/60”却不说明它是规模。

需要比较食品份额时，复用[层内占比标注](../../semantic-marker-anchors.md)及[已有 Mekko 实例](../../../examples/semantic-mekko-layer-share.json)：`hierarchy-diff-line` 的业务 target 用 `match`、`metric:"食品"` 和 `boundary:"start"`，标签用 `layerShareDiff`。本例 A→B 为 −35 个百分点，不是 −35% 相对变化，也不是收入差额 −45。数值结论由动态标签表达，不抄成静态文字；业务 target 首次物化后的维护边界遵循原生标注契约。

小区域标签应使用可读位置或 Tooltip；不能承诺自动避让，也不能仅缩小字号声称所有信息可读。需要单项标签或样式时沿[标签协议](../../labels.md)取得真实身份，不凭组成列序号猜单图元 key。

## 4. 交付检查

按[工作流校验](../../workflow.md#commonoption-交付前校验)检查完整配置。另核对组键、总量是否只计一次、组成完整性、非负值、逐组分母、带宽映射及排序；JSON 合法不证明业务口径一致。有效宽度比与高度比分别核对，标注应表达份额百分点而非绝对值或增长率。

开发验收覆盖单项组成编辑的静态带宽边界、同步更新组成与总量、排序、撤销重做、保存重开、窄分段及 PNG。模型工作流、真实宿主和来源同步分别记录；配方与固定示例不证明这些验收已通过。
