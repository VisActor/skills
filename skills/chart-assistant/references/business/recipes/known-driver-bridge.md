# 已知贡献利润桥

用于从起点利润或现金，经已给定的有符号贡献到计算终点；复用原生 `waterfall`，不新增归因算法或保存协议。可直接加载的[利润桥实例](../../../examples/business/known-driver-bridge/common-option.json)使用合成数据和已知单位万元，不把示例期间、单位或贡献带入用户数据。

## 1. 确认贡献事实

需要起点、按业务顺序排列的已知贡献、同口径单位与期间；源终点若存在，单独核对。起点与终点是存量，贡献是增量，累计小计是检查点，三者不得混作贡献求和。

- 只给两期利润，只能比较主值；请求已知贡献或认可的归因方法，不猜销量、价格、成本等经营原因。
- 缺失贡献不补零；重复因素不静默合并。核对唯一业务键以及期间、单位和范围；混合口径先澄清。
- 用户给出累计小计时，先核对它等于此前累计结果；不把累计值再次加入。不一致的小计保留源值并说明差额，不静默换成计算值。
- 保留业务逻辑顺序，不能按贡献大小排序后仍声称原桥接路径。跨零或负利润不等于数据错误，也不能自动使用增长率、改善／恶化评价或有利／不利色。

## 2. 原生总计与小计

单指标普通 `waterfall` 使用 `mappingSpec:{"x":"驱动因素","y":["影响额"]}`。首行保存数值起点，在 `series-waterfall` 的完整 `modelSpec` 包装中设置 `firstToTotal:true`；显式末行和中间小计使用模板总计标记 `"e"`（也接受 `"E"`）。它们展示当前累计值，不作为新增贡献。显式末行存在时设置 `addLastTotal:false`，避免再追加一个总计。

```json
{
  "id": "series-waterfall", "specKey": "series", "specIndex": 0,
  "spec": {
    "stackType": "group", "groupBySign": true,
    "firstToTotal": true, "addLastTotal": false,
    "label": {"visible": true}, "totalLabel": {"visible": false}
  }
}
```

实例依次是：起点 100、销量 +25、价格 +10、收入贡献小计 `e`、原材料成本 −18、其他费用 −7、期末利润 `e`。小计显示 135，终点显示 110；135 不重复累计。把 −18 改为 −20 后小计仍为 135，计算终点为 108。不得用普通数值 110 作为末行增量，也不得把源小计 135 作为贡献行。

这里的 `e` 是计算检查点，不保存用户独立给定的源终点。仅当源小计／终点已与计算一致，或用户明确授权展示计算终点时，才能用 `e` 代表它；另行保留来源事实与核对结果。对于 Sheet direct-live，不为了插入 `e`、转换存量为增量或追加总计而改写读取数据；按[来源契约](../../sources-and-sync.md)核对模板是否能直接消费原形状，不能转换后继续承诺自动同步。

## 3. 源终点冲突

起点 100、贡献 +25/+10/−20/−7 的计算终点是 108，源终点若为 110，差额是 `源终点 − 计算终点 = 2`。保留原始贡献和源终点 110，回复明确说明计算 108 与差额 2，并请求遗漏贡献或口径解释。不能把 −20 改回 −18、把源终点改成 108，或虚构“其他贡献 +2”凑平。

口径未解释时不得交付声称桥已完整解释源终点的图。可以交付独立授权的“已知贡献计算桥”，其末行明确命名“已知贡献计算终点”，同时说明源终点仍未解释；源终点不作为普通数值末行加入。若用户只要求完整源终点归因而未授权部分结果，则澄清后再建图。初次核对结论不是数据绑定：后续手动改数不会自动生成业务口径告警或更新回复中的源值、差额说明。

## 4. 稳定主题与样式

按 [MBB 规范](../../mbb.md)继承字体、留白及已知单位。新建默认标题为“已知期间＋指标＋已知贡献桥”，如“2026 年利润已知贡献桥”；期间未知时省略，不编造日期。标题、次级说明与独立文本不写死当前净变化、终点或增长／下降结论，数值由原生数据标签与计算总计表达。用户明确要求结论标题时核对当前事实，并说明它是静态文本、改数后需手动更新；已有图只改授权范围。

单指标按[瀑布方向配色](../../waterfall-colors.md)使用总计、增加、扣减三类颜色；示例总计深蓝、增加蓝、扣减暖红表示累计方向，不代表业绩好坏。组键按真实指标名及宿主语言确定；多指标或既有 stack 图不能照抄 group 三键。明确业务定义前不把正贡献叫“有利”、负贡献叫“不利”。

如需强调某项已知贡献，复用 `markStyle[].target:{selector:{"驱动因素":"原材料成本贡献"},measure:"影响额"}`；样式与业务事实分开。Marker 使用自己的 `match/metric` 契约，不能混用。语义样式首次物化后保存原生身份，不承诺持续重放或自动按变化方向切色。

## 5. 交付检查

按[工作流校验](../../workflow.md#commonoption-交付前校验)核对完整配置。检查首行总计、贡献符号、原顺序、每个小计与最终累计、源终点差额和标题静态限制；只检查 JSON 合法不能证明桥的事实正确。普通标签、单位和方向色要对应真实渲染，不把原生 `totalLabel` 与总计柱混淆。

开发验收覆盖改数、撤销重做、保存重开、单因素样式与 PNG 完整边界。来源资格与真实宿主编辑、重开、导出、同步独立验收；本配方及固定实例不证明模型评测或真实宿主验收已通过。
