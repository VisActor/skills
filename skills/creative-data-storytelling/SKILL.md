# 创意数据叙事

**好的作品 = 好的叙事编排 + 好的可视化设计。** 从主题、数据、文本档案或已有研究与设计出发，把“发现了什么”转成“读者怎样在画面中发现它”。沿用用户已确定的范围与决定。

本版默认面向 PC 浏览器，按实际桌面窗口设计与验证，也检查笔记本可用高度。新作品将实现精力用于完整画面、连续阅读和可靠交互；移动布局与减弱动态分支按用户要求或已有项目规范提供，不作为默认附加工作。

## 作品如何组织

以**随滚动持续演进的全出血舞台**为主要表达方式。“全出血”指视觉延展到视口边缘；“持续舞台”指同一视觉区域跨多段阅读保持可见，保留重要对象和参照，随叙事展开关系。单张图已能表达的发现、背景和补充材料可正常滚动阅读；段落高度随内容安排，文字与操作保留舒适边距。

| 概念 | 职责 |
| --- | --- |
| 作品 | 围绕主问题组织完整阅读体验，包含必要的引入、解释与收尾；可按问题加入探索 |
| 章节 | 围绕一个问题或分析阶段组织的叙事段落 |
| 舞台 | 承载一段解释过程的视觉区域，让对象、参照和交互跨多段阅读持续存在 |
| 阅读状态 | 舞台中可以停下来理解的完整画面；可以由多段文字共同解释，不等同于一页或一屏 |
| 衔接 | 状态之间的变化，交代对象、数据或观察方式的关系 |

章节、舞台、段落与状态不必一一对应。先推敲实际文字与构图，再决定哪些内容共享舞台、哪些自然接续。

## 创作方向

叙事取舍与可视化构图共同推敲：从这一段要推进的理解出发，按数据关系与阅读需要[选择表达](references/visualization-design.md#从关系选择表达)，再设计前后衔接。整体与局部、比较、变化、累积和重组可交织；时序提供联系，阅读顺序由问题决定。单元组织、序列对齐、实物承载等手法可以组合，也可设计新的表达。

## 设计判断

- 正文的关键关系在图中应有可见证据，当前问题决定主画面与参照。
- 素材与运动可以解释数据，也可以建立主题和沉浸感；量值映射保持正确。
- **有解释意义的画面可以停留，只负责连接的画面应自动完成。** 讲发展变化时，让历史仍可比较，突出当前重点。
- 探索沿用已建立的读法，让简洁操作回应值得追问的问题。

稳定身份、真实来源、共同口径和正确比例是底线。叙事、构图与美术需要阅读判断，结构完整与代码通过只是其中一部分。

## 交付

研究交付可追溯的数据与发现；设计交付关键构图及衔接理由；实现默认交付静态 HTML 与必要资源，附打开方式、来源与实际检查记录。完整作品的设计稿写法见工作流；单文件内联按用户要求处理。

适用的控制和计算直接调用 `assets/runtime/`；示例装配供参考，构图由作品设计。接口、工具选择和交付接法见[实现参考](references/implementation.md)。
