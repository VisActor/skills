# 创作工作流与设计稿

沿用用户已有方向与授权，从当前阶段进入。完整创作自主推进；用户要求分阶段审阅或缺少关键输入时再停下。

## 研究到构想

1. 确定读者、材料范围与交付要求，只询问会改变结果的缺失信息。
2. 按[数据与证据](data-and-evidence.md)整理可比较的记录、候选发现与来源，区分事实、待解释的关系和证据边界。

## 构想到画面

3. 按[设计指导](design.md)组织主问题与证据顺序，确定关键段要让读者看清的数据关系及[表达方向](design.md#从追问选择表达)；用户已有设计时沿用确定的决定。
4. 用[选择表与 inspect](design.md#从追问选择表达)读取相关示例的具体解释，候选也可包括用素材回答相近问题的片段。结合真实数据、相邻正文与[代表素材](material-direction.md#与关键画面一起规划)推敲构图和衔接，将本作品的决定写入下方设计稿。

进入实现前，关键关系的构图与交接应已明确；具体像素、缓动和非关键细节可在制作中细化。

## 试作到完整作品

5. 先实现最容易牵连全文的关键过程。新建滚动舞台按[正文接法](implementation-stage.md#选择正文接法)接入 `connectReading`，用作品自己的数据、布局、过渡与绘制替换短例；已有可靠接线可沿用。改编示例时按需读取相关代码，带上相邻正文与代表素材，在桌面窗口观察关系怎样形成、整幅图文怎样进出；具体运行故障再查[诊断接口](implementation-rendering.md#实际占位与空间诊断)。这段直接属于最终作品，不另建试作报告或审批。
6. 解决关键过程后扩展其余段落，完成全文布局、正文与交互；试作改变设计时同步设计稿。
7. 从最终交付入口按[作品验收](quality.md)完成一次实际阅读与关键操作，结合已有数据核验和有效的资源审计，判断硬门槛与整体质量。按作品需要核对快切／倒回、缩放后的同步或筛选结果；诊断工具只辅助定位问题，采集完成不代表验收通过。集中修复影响事实、阅读和操作的问题，只复查受影响项，简记质量判断、验证依据和未验证范围。

## 三种回退

| 发现的问题 | 返回哪里 | 保留什么 |
| --- | --- | --- |
| 结论依赖缺失的分母、事件或身份 | 研究 | 已核对的数据与来源 |
| 画面读不出关系，或章节彼此独立 | 叙事／构图 | 成立的发现和可用素材 |
| 设计清楚但卡帧、错位、素材露边 | 实现／素材加工 | 已确认可读的布局与正确的量值映射 |

## 可修订的设计稿

完整作品保留一份简洁的 `story-design.md` 或沿用用户分镜。按完整解释过程组织，粒度随难度调整，不把每段正文写成一屏。

**整篇交代两条线：** 叙事线说明读者的起点、主问题、证据顺序与最终判断；可视化线说明承载它们的对象、表达关系与读法。共用的视觉语气、排版和素材方向简记一次。

**随后按阅读顺序，将关键过程的文字和画面放在一起：**

| 设计决定 | 写到什么程度 |
| --- | --- |
| 新增理解及依据 | 这一段怎样推进主问题，使用哪组记录、比较条件与关键结果；直接引用已有数据，不复制研究过程 |
| 读者读到什么 | 开篇、关键过程与收尾拟用于页面的文字，以及必要的图内标签；按顺序能读出追问、发现与回答，而非“这里解释、这里总结”的制作备注 |
| 画面怎样提供证据 | 对象、编码、基准与空间安排，以及发现具体出现在哪里；可用简图或足以还原构图的文字。取用片段时注明 ID、沿用的设计与必要改动，不重复抄写示例说明 |
| 怎样接续 | 沿用什么理解、对象或基准；需要变化时，谁保留、怎样变化、何时到达可停留的结果；静态图文交代阅读关系即可 |

素材与探索参与时，就近写明用途、取得方式或操作结果。引用片段不替代本作品的实际正文和前后承接，也不另写选型报告。设计备注与页面正文分开，见[正文与图形分工](design.md#正文与图形分工)。

简短片段示例（模拟项目，只说明设计的具体程度）：

> **要推进的理解：** 已按类别比较项目数量，接着判断总投入是否也按同样顺序排列；数据有每个项目的类别与服务时长。
>
> **正文：** “项目最多的类别，投入的时间也最多吗？每个项目需要的时间并不一样。”
>
> **画面与接续：** 前图每行一个类别，等大方块代表项目，从同一左端排列。下一段出现时，类别次序、项目身份和颜色保留；方块变成等高、长度代表小时数的分段，并在各行首尾相接。刻度切换为共同的小时尺度，各行端点显示总时长，类别名旁保留项目数量。这样可直接比较哪些类别项目多、哪些类别总投入高。变化自动完成并停留在完整结果，之后正文再解释一个有代表性的项目。

该例说明记录应具体到能还原证据与衔接，不限定采用长度编码或这套排列。

## 研究、设计与验收各自记录什么

| 内容 | 放在哪里 |
| --- | --- |
| 原始来源、清洗口径、计算和候选发现 | 已有数据与研究记录，供设计引用 |
| 当前叙事取舍、正文、构图及衔接 | 设计稿；试作改变选择时更新相应段落，保留必要理由 |
| 硬门槛核验、整体质量判断及问题修复 | 交付说明或已有检查记录，按[作品验收](quality.md#记录与修订)注明实际范围与未验证部分 |

沿用已有文件，每项内容保留一处，其他记录引用它；不为文案、开篇、动画或逐轮试作另建报告。
