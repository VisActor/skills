# 叙事编排：让证据接起追问

好的叙事是一段经过选择和安排的认识过程：让读者愿意进入，借助证据逐步看清一个问题，并在结束时获得比开篇更完整的理解。本页负责这段过程；[单元可视化设计](unit-visualization.md)负责让其中的关系成为可见证据。两者共同记录在一份[设计稿](#把叙事与画面写进同一份设计稿)中，画面中出现的新发现也可以改变故事线。

## 什么算好的叙事

以下是设计与评议共用的标准，不是六个必备章节。认识可以是理解一个群体、看清变化、学会比较或修正直觉；清楚的描述同样有价值，不要求反转或戏剧冲突。

| 标准 | 编排时作出的决定 | 在作品中怎样判断 |
| --- | --- | --- |
| 有值得获得的认识 | 从读者关注选定主问题，区分题材、统计事实及其意义 | 读完能说清对这个问题多理解了什么，依据能回到材料 |
| 各段确实推进理解 | 选择主线证据，安排必要背景、解释与回看，其余放入详情或舍去 | 删除或合并一段，会失去哪项理解或必要的阅读节奏；只是又多看一个字段，贡献还不够明确 |
| 顺序有解释上的理由 | 先建立后续所需的对象、参照和比较条件；并列角度各有职责 | 下一段接住前段的问题、补充或修正认识；并列证据最终能合起来回答主问题 |
| 信息在需要时出现 | 开篇建立识别与期待，首次读图交代单位，关键比较留出阅读空间 | 读者不用先解码整套分析才能进入；需要某项背景时已经得到，图文落定后有机会看清 |
| 证据在画面中成立 | 正文的重点对应可见的差异、结构、过程或身份线索 | 保留必要图例、暂不读结论文字，仍能指出主要关系；精确读数和解释文字继续提供细节 |
| 收尾兑现开篇期待 | 综合已建立的证据，回答或修正最初的问题，说明影响判断的边界 | 结尾所得有前文依据；后续探索延续已学会的比较方式和有用追问 |

判断单位是一段完整解释及整篇阅读过程。背景、停顿与总结可以不增加新数据；个别段落换顺序仍然成立，也不意味着叙事无效。事实可核对、比较条件一致、描述与原因分清，是这些设计判断的基础。

## 从用户关注点选择值得讲的发现

先明确读者带着什么经验进入，希望弄清什么，现有材料能把理解推进到哪里。用户已有具体问题或创意时沿用；只有主题时，从材料中寻找可以回答的问题。数据整理见[材料与粒度](unit-visualization.md#整理材料与确定粒度)。

主题可以是“作品与阅读量”；问题可以是“作品更多的类别，是否也获得更多注意力”。对候选发现判断三件事：与用户关注有什么关系；读者会多理解什么；总体、分母、时期、分类与来源是否支持这个理解。

例如，某类记录增加，可能来自覆盖范围扩大；某群体均值相近，其分布与尾部却可能不同。核对条件可以找到主线，也可能推翻原设想。补材料是为了回答必要问题；已有证据只支持描述时，讲清变化与关联，原因另需依据。

题目宽泛且存在不同解释方向时，先简短比较候选主线：各自带来什么认识、有哪些关键证据、材料缺口在哪里。选择值得讲且能够讲清的一条，不按数据列名生成目录，也不为每个任务凑固定数量的方案。

选定后，用一句话写清主问题，以及读者最后应形成的认识；再区分主线证据、理解它所必需的背景和可按需查看的细节。设计中的结论随证据修订。

## 把发现编成连续的追问

围绕主问题，把核心发现组织成读者能够跟随的解释段落。每段先确定读者从什么认识出发、到段末要看清什么，再把完成这次判断所需的证据连起来。例如，已经看到总量增加，接下来可以拆开新增来源，也可以核对覆盖范围；各自回答不同问题，画面中的参照与变化也随之不同。

将这一段的关键画面按阅读顺序连排，借助[表达与衔接](unit-visualization.md#从叙事追问推导表达与衔接)共同推演：读者先认出了哪些对象或结构，下一步从其中选出、展开、比较或重新理解什么。后续要比较的对象先在画面中建立身份，后续要检验的判断先给出可回看的依据。已有画面能继续解释时，可以让正文接着展开；需要新证据时，再改变组织与视角。

前后构图可以相互调整。例如，下一步要细看某个群体，前一步就需让它在总体中可辨；下一步要比较增量，前一步就需建立各组原值。若某个表示只适合当前结论，却使后续来源难以辨认，就回改范围、排列或追问顺序，再决定动画。数据可比时，也可以用新的独立样本延续共同尺度，无需假装同一批个体。

新角度根据解释职责安排位置：补足下一步比较所需的背景，解释刚看见的特征，或检验已形成的判断。并列分析也可以成立，需明确它怎样共同回答主问题；不必为多展示一个指标中断正在展开的比较。独立材料可以补充原因或生活影响，不为它们编造数据上的转换。先连起这段观察，再划分可停留的状态与[舞台边界](#先划解释段落再决定舞台)。

为重要连接写清：

> 读者已看见＿＿；接下来要判断＿＿；依据＿＿之间的关系，对已有画面进行＿＿，并保留＿＿作为参照。

把具体对象、数据关系与操作记入既有设计稿。随后连读整段，检查开头建立的对象、问题或比较基准在后文怎样得到展开、检验或回答。相邻画面接得顺，还需要合起来完成本段的判断；身份对应与运动风格再按[运动指导](unit-visualization.md#由前后关系设计运动)细化。

### 同一份数据，故事线可以不同

假设同一观察窗口中有十件作品：A 类六件、共获九十次阅读；B 类四件、共获一百五十次，其中一件获得一百二十次。这是说明推导的虚构数据。

若关心“作品更多的类别，是否也获得更多阅读”，可以连起这段认识：先知道 A 类作品较多，再发现 B 类作品较少、阅读却更多，随后检验这个类别总量是否由少数作品撑起。最后读者需要区分类别总量与单件表现。数量比较建立两类身份，贡献比较接住它们，类内展开再检验刚形成的判断。具体画面如何共同设计，见[连续构图推演](unit-visualization.md#数量与贡献)。

若关心“注意力是否集中”，可以从那件获得一半阅读量的作品进入，保留它的身份并展开其余作品，形成个体与总体的比较；再看其余贡献怎样分布。类别只在帮助解释集中时出现，此时先介绍所有类别数量会延迟回答核心问题。

两条线组合了不同的追问与画面操作，不要求按表格顺序选择。阅读量支持贡献与集中程度，不自动说明作品质量或流行原因。

## 开篇与第一项证据一起设计

面向普通读者，开篇用简洁的标题、短引入和主体画面建立主题感与继续阅读的理由，集中呈现一个容易进入的重点。较长的背景与解释、成组指标和读图说明随正文与第一项证据逐步展开，不在首屏堆齐。确有引入价值的数字或比较可以保留，前提是对象、单位和关系一眼能懂，无需先学会图例、坐标、分组规则或交互操作。简洁取决于读者需要理解的事情有多少，而不只是元素数量。

**先确定读者为什么进入。** 从整篇主问题选择值得遇见的人、物、情境、反差或疑问，明确它与后文要讲清的认识有什么关系。也可以用主题形象或文字构图建立体验，不必每次制造悬念。入口越具体，后文越需要回应这个对象或经历；先想清吸引读者的内容，再决定采用什么形式。

**再选择主体要保留的特征。** 人物身份、物件外观或场景细节若是入口的吸引力，选表达时就读[素材指导](material-direction.md#先确定素材承担什么)，查看代表素材，再决定采用原图、插画、轮廓或简化符号。概括有助于突出共同特征，也可能丢掉具体对象的独特性；取舍依据是当前入口需要什么。格式与绘制工具随后选择，照片或粒子 logo 都不是必需。

**让标题与主体共同形成构图。** 用实际标题、短引入和代表素材安排第一眼的视觉中心：选择能显出主体特征的视角或局部，让形象与文字形成明确的分量关系，用留白、色彩与字形组织视线，具体见[视觉样式](visual-style.md)。主题可辨只是起点，还要让题材本身的特征成为画面的吸引力。文字也可担当主视觉，形象与运动可以营造主题感，不必同时编码数量。轮廓与单元的处理见[主题形象](unit-visualization.md#主题形象与静态素材)。

**由入口的期待安排第一项证据。** 保留读者刚认识的对象、经历、参照或追问，让下一步展开、检验它，或建立理解它所需的基准。可以先铺背景而暂不回答，但应让读者知道为什么先看这里。换时期、指标或观察范围时，交代新证据怎样帮助理解原来的问题；延续同一种单元或动画本身不足以建立这种联系。开篇可以同台进入数据，也可自然滚到下一段；按两端的含义设计动作，标题、引导与图形共同交接，第一项证据要有真正的阅读机会。

例如，沿用上文十件作品的虚构数据，若从那件获得一半阅读量的作品进入，可以让其封面与标题「十件作品，一件分走一半阅读」共同构图。封面让读者认出具体作品，大小暂不编码阅读量；第一项证据保留它的身份，展开全部作品的阅读贡献，让“一半”成为可见比较。先展开类别数量则需另有解释理由，因为它暂未回应注意力集中的问题。这里示范选择与承接的依据，不规定封面式开篇。

把这组实际图文纳入既有试读：主体与短文字能否建立兴趣，是否仍有可以后置的解释或指标，视觉中心和关键特征是否清楚，第一项证据是否接住了期待。形象负责识别时，暂去掉名称，看实际尺寸与缩略视图是否仍可辨；文字负责引入时，看措辞、字形和排布是否共同成立。上述是相互校正的设计决定，不对应固定屏数、必做方案数量或额外检查轮次。

## 阅读组织与停留

### 先划解释段落，再决定舞台

先把核心数据解释连成持续演进的全出血主舞台，从已有画面推导下一步，再划分阅读状态。章节组织追问，舞台承载这段共同观察；章节标题、换时期、换指标或换图形本身不决定换场。

1. **在舞台内展开追问。** 根据[追问与表达的对应](unit-visualization.md#从叙事追问推导表达与衔接)选择操作，让读者看见选择、展开、对齐、重组或时间更新怎样产生下一项证据。布局和尺度可以改变，必要时同台并置多个视图；延续的是有用的身份与参照，不是所有对象的原位置。
2. **给解释留下停留。** 当前画面已能支持下一段说明时，保持证据，让正文继续展开；需要新比较时再响应。静态可读的状态同样属于连续叙事，不为保持运动而制造变化。
3. **在阅读任务确需改变时结束舞台。** 当前共同观察已经完成，接下来如需细读档案、人物经历或独立材料，可以进入正常图文。新数据问题若需要独立空间，先判断重排、缩放或并置是否可继续解释；仍会混淆对象与基准时再换场，并写明新空间带来的具体收益。

连续性依靠仍有解释职责的对象、历史与比较基准。可以保留关键时期、历史轮廓或缩略全景，不必把完整旧图叠成永久背景；独立样本也可以靠共同尺度连续比较。固定容器内淡出旧图、换入另一张成图，仍需说明它怎样承接已有理解。

### 用空间与停留支持这一段解释

把实际正文与关键画面一起编排：正文提出当前要判断的问题，交代背景、口径和意义；图形显出支持判断的差异、组成或过程；动画交代已有证据怎样形成下一项比较。数值标签提供精度，原因和背景可以由文字解释，不要求图形脱离文字说明一切。若正文说的是增量，画面就应能找到增加的部分，而不只是前后总量。图中显出的新关系也可以改变正文与顺序。

正文可以自然经过，也可以在舞台内交接；一幅图可支撑多段解释，一段文字也可引出多个变化。文字长度由解释任务决定，图形状态不限制正文段落。继续解释时保留可观察的证据，新的观察需要改变画面时再响应。

正文与图形共同编排：追问或观察提示可以在变化开始前后进入，图形随之回应，精确读数与结论在相应证据可读时交接。这些过程可以重叠，不把整段正文、轴和标签统一排到动画结束后出现。自然滚动的正文继续经过，原位正文可以局部交接；持续有效的参照保持可见。各层时机见[语义交接](implementation.md#文字图例轴和单元一起交接)。

按比较方向、记录密度、正文长度与变化范围分配空间，见[舞台空间](unit-visualization.md#舞台空间与辅助信息)。先画关键构图，再选侧栏、浮动文字或上下组织；同段维持有用的空间参照，新解释可重新安排。整篇相同或不同布局都不是质量目标。

有时间字段时，选择有解释意义的时期、变化和转折：可以沿过程推进，也可以从结果回看基底，再比较群体。保留支撑发展判断的历史，普通时期可以经过，重要节点需要读清；完整覆盖不等于逐年停留。

每个关键状态区分两件事：连接完成后的图文是否一致；正常向下阅读时，完整证据是否仍在可用区域内。关键比较需要观察机会，不能要求用户在短暂动画终点恰好停手。连接由时钟完成，停留空间由正文、触发位置与舞台长度共同安排，具体见[时间与语义交接](implementation.md#时间与语义交接)。

## 收尾与简洁探索

结尾用前面的证据回应主问题，也可修正最初的提问或解释为什么只能回答到这里。可以回到全景、并置重要判断或停在代表记录；选择由最终认识决定，不再添加一组与主线无关的指标。

有值得继续追问的问题时再安排探索：先确定一个问题、一项主要操作和一种可见结果，例如换时期比较分布，或选择记录看它在同类中的位置。结果可以是差异、例外或具体依据，不必总是惊人的发现。

沿用已经教会的视觉语言。涉及变化就保留比较基准；查记录就提供可辨认入口；额外维度有帮助再加控件。状态管理见[实现参考](implementation.md#主线与探索)。

## 把叙事与画面写进同一份设计稿

保留一份可修订的 `story-design.md`，已有用户分镜可以沿用。先记主问题与各解释段落的作用，把关键段的追问、画面和承接按阅读顺序放在一起；其余先记作用与依据。按[创作流程](../SKILL.md#从当前任务进入)决定是否先试作尚有疑问的段落；实现后引用已有画面位置和数据依据。文档保留当前决定，不重复维护网页全文，也不要求先做完整设计稿网页。

| 内容 | 留下能指导实现的决定 |
| --- | --- |
| 整体构想 | 主问题与最终所得；贯穿解释的对象和参照，主要构图与操作怎样接成一条可观察的线索 |
| 追问与数据关系 | 读者已经知道什么，下一步要比较哪些对象、属性或组成关系，为什么接在这里 |
| 证据依据 | 引用支持本段的数据、来源与计算位置；记清会影响画法或解释的单位、总体、分母和边界 |
| 画面与操作 | 连排关键段的画面构想，实现后引用实际图文：当前画面怎样显出重点，又为下一步留下哪些可辨对象或参照；提取、展开、对齐或重组怎样形成新比较，标明单位、尺度与必要素材 |
| 正文与阅读 | 正文何时引导操作，证据与结果何时可读，哪里需要停留；必要换场怎样接住已有认识 |
| 视觉样式 | 字体与数字角色、主要层级、颜色含义及间距；用真实图文验证，具体依据见[样式指导](visual-style.md) |

构想阶段可以画草图；实际片段用于判断真实数量、极值、正文与素材能否共同支持比较。例如，“保留共同坐标”仍需在画面中看见比较双方和有辨识度的差异；“保持身份”仍需有读者能认出的对象或参照。把具体取舍写清，比重复“连续、清晰、有吸引力”更能指导后续实现。小范围任务可以合并条目；计算与来源沿用已有记录，引用所需位置即可。

随[创作流程](../SKILL.md#从当前任务进入)将改变的决定更新到同一份稿件，保持当前方案。交付检查记录保留实际结果、必要证据与影响交付的限制，无需逐次记录样式微调或尝试经过。

## 叙事检查

沿用[开头的六项标准](#什么算好的叙事)，把设计稿的承诺与作品中的具体证据对照，不另造一套完成度评分。

连读实际标题、正文和关键画面，说明主问题如何被推进与回答。重点看核心解释是否在舞台中真正展开：相关发现是否被过早拆成各自的成图与结论，或无共同观察价值的内容是否仍被硬塞在同一容器。按上面的选择顺序重新判断边界。

记录影响理解的具体判断：正文让读者比较什么，图中哪部分承担这个比较，前后如何接起来。例如，“同一尺度”说明条件一致，还需看清本段比较的是总量、增加部分还是间隔。主线与关键证据成立后，继续完成作品；精修的取舍与[首稿流程](../SKILL.md#从当前任务进入)一致。

故事线成立但证据看不出来，回到[视觉检查](unit-visualization.md#单元可视化的阅读检查)；只有落定状态可读、实际滚动跳过证据，回到[实现指导](implementation.md#给完整证据留下阅读区间)。这些判断并入[同一次实际试读](implementation.md#实现后的检查)，不另开检查轮次。成品正文用于解释事实、引导必要操作和说明证据边界；作者为什么选择这种设计、如何实现动画，留在设计稿。
