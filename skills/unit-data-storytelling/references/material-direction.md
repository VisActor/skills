# 素材选择与准备

普通矢量图和静态图片可以建立主题，也可以直接成为数据单元。先明确素材在当前画面中帮助读者认出什么、比较什么，再选择来源、形式和处理方式。素材本身可以保持静态，随单元排列、移动、突出或进入详情。

本页负责选择与准备；叙事中的使用时机见[开篇与第一项证据](narrative-design.md#开篇与第一项证据一起设计)，编码与构图见[单元可视化设计](unit-visualization.md)，实际绘制见[素材单元接口](implementation.md#素材单元)。SVG 舞台同样可以使用 PNG、WebP、JPEG 等图片，渲染技术不限定素材格式。

## 先确定素材承担什么

| 素材职责 | 可能的形式 | 与数据的关系 |
| --- | --- | --- |
| 配图与引入 | 一个人的照片、物件图、情境插画、档案片段 | 建立对象感、背景或阅读兴趣，接到正在提出的问题；可以不承担数量含义 |
| 识别具体记录 | 一部作品的封面、一位人物的肖像、一个机型的产品图 | 素材与对应记录相连，核对对象、版本或时期；详情可以恢复更丰富的原图 |
| 识别类别 | 国旗、设备图标、交通方式的轮廓 | 相同符号可用于多条记录，表示所属类别；记录仍各有自己的身份 |
| 表示固定量或份额 | 重复的人物符号、物件图标、简洁图形 | 每个单元的量或比例明确定义，余量按[单元口径](unit-visualization.md#整理材料与确定粒度)处理 |
| 提供主题构图的母形 | 轮廓 SVG、字形或静态遮罩 | 提供排布位置或主题识别；轮廓中的位置通常没有统计含义，数据单元与装饰碎片分别管理 |

这些职责可以组合：一张封面先引入作品，再缩小后回到全部作品的排列中。一个类别图标也可以代表固定数量，但图例要交代数量单位。具体对象的照片与一般类别符号，让读者获得的认识不同；选择符合当前问题的精度。

在已有[设计稿](narrative-design.md#把叙事与画面写进同一份设计稿)中简记素材对象、职责、关联记录或类别、拟用尺寸与来源。先用代表素材试一幅真实构图，再决定是否准备整组，不按章节数量分配图片。

当开篇或人物、物件的识别是解释的一部分，优先选用能保留身份与主题感的代表素材，在实际构图中检查。需要兼顾密度或难以取舍时，再比较真实素材与简化符号。素材可服务开篇、重点与详情，其余保持紧凑符号。取舍依据放在设计稿，不把未搜索、未试用写成“没有合适素材”。

## 从哪里取得，怎样选择

先检查用户材料和数据记录中已有的图片、链接、标识或封面字段。需要补充时，按对象的事实精度和美术要求选择来源：

| 来源路线 | 适合的需求 | 取得时核对什么 |
| --- | --- | --- |
| 用户提供的文件、记录关联素材 | 已有对象、档案或明确艺术方向 | 文件是否对应当前记录，版本、时期与覆盖范围是否一致 |
| 对象的官方页面、品牌素材页、出版方或机构档案 | 准确认出产品、人物、作品或历史对象 | 具体型号、作品版本、拍摄或制作时期；找到实际文件及其来源页面 |
| 博物馆、图书馆等数字馆藏与原始档案 | 器物、历史图片、扫描件 | 对象说明、年代、归属与使用条件；扫描边框是否值得保留 |
| 有清楚来源的矢量或图标集合 | 类别识别、重复单元、简洁轮廓 | 同一套的风格与覆盖度，实际文件格式、小尺寸表现及使用条件 |
| 原创绘制或图像生成 | 一般物件、主题插画、原创符号 | 按构图制作；生成的形象与真实档案分别说明，精确身份仍以对应资料为依据 |

搜索时使用对象标识、版本或时期，再加素材形式、视角等条件。发现候选图后回到来源页核对，不只保留搜索缩略图。按交付需要取得可加载文件并保留出处；来源链接本身不能替代作品里需要实际显示的素材。

素材记录可以并入现有数据或来源文件：保留本地路径或资源地址、对应对象、出处与使用条件，经过加工时再记处理方式及必要提示词。类别图标按类别关联，记录图片按记录 ID 关联，素材文件名不充当对象身份。先检查整组覆盖情况；缺图的记录继续保留在数据中，可以用一致的简化符号并保留名称与详情。

## 选择矢量还是位图

**简洁图标、清晰轮廓和需要改色的符号**，可采用可靠的矢量或自行绘制 SVG。简单几何适合代码绘制；复杂人物、物件细节或特定美术风格，按素材条件使用现成图形或图片。需要实际矢量时检查文件内容；“矢量风格”的生成图片仍可能是位图。

**真实人物、产品外观、封面和档案**，通常采用对应照片、原图或扫描件。图片可完整显示、置于一致的容器中，也可按构图提取主体。是否抠图取决于需要独立排列的对象边界；封面本身的矩形边界往往就是识别的一部分。

按实际最大显示尺寸准备清晰度，保留宽高比例。小单元可使用简化素材，选中或放大时再显示细节版本；两种外观关联同一记录。数据标签、坐标刻度及精确量值几何由网页生成，便于更新和核对。

## 把一组素材放入共同构图

单元表达需要看整组，而不仅是单张图片的质量。先试用长宽比例不同、细节多寡不同和最难辨认的几份素材，检查实际显示尺寸与最密集状态。

- **视觉大小与锚点。** 同样的图片框不代表同样的主体大小；先检查透明留白、主体边界、视角和裁切，再选中心、底部等锚点。保留对象比例，调整留白或展示框，让等大单元具有协调的视觉分量。
- **识别与比较。** 颜色、纹理和真实外观本身也会吸引注意。协调同组素材的视角、线条和细节，保留身份差异；需要额外类别编码时可用邻近标记、边框或分组标题，避免改色后损失国旗、封面等原有识别信息。
- **大小是否表示量值。** 等高展示的产品图或头像通常只是身份标记。若需要面积或长度编码，按数据计算几何并提供清楚参照；不同轮廓的填充面积不能仅靠相同外接框比较。可以让素材负责身份、圆点或条段负责精确量值。
- **密度与层级。** 在密集状态中确认单元仍可辨和可点选；可以将完整图片留给重点与详情，其余使用简化符号。图标中若包含多个人或物，也要检查它是否会让“一枚单元”的含义变得模糊。
- **前后连续。** 同一记录换排列或换外观时延续数据锚点及必要的身份线索。图片从详情回到群体时，让读者认得出它属于哪一枚单元；换批记录则按[前后数据关系](unit-visualization.md#由前后关系设计运动)交接。

整体到局部可能需要更大、更清晰的原图，也可能只需要同一张图换位置。素材准备跟随具体构图需要，不预设每条记录都必须有多个版本。

## 静态图片与透明背景的准备

取到文件后先查看原图。核对对象、实际尺寸、主体边界和背景，再决定保留原貌、裁切、缩放或去背景。原图与加工结果分开保存，便于回查和重新处理。

需要独立主体时，使用当前环境可用的图像编辑或抠图能力，输出支持 alpha 的图片。保留完整主体和关键识别特征，检查边缘残留、细部缺损和阴影是否适合舞台背景。透明 PNG／WebP 的扩展名不保证文件真的透明；同时查看 alpha、浅色及深色背景上的边缘。白底图使用 multiply 只是混合效果，不能作为抠图完成的依据。

无法得到干净主体时，可以换一张来源图、采用有意设计的图片容器，或改用简洁符号。普通静态素材的整体移动、排列与强调通常足以承担单元表达，不需要先拆分身体、关节或物件部件。

## 生成与编辑的提示词

需要生成时，将当前构图的要求转成制作输入；编辑已有图时，明确目标图与参考图的职责。按需要写清：

```text
用途与含义：用于引入、某条记录、某个类别，还是主题轮廓；读者要认出什么。
对象与输入：需要保留的对象特征；编辑目标、身份参考与风格参考分别是什么。
构图：视角、完整边界、画幅、主体占比、锚点所需的留白。
成组要求：与已选素材保持协调的视角、细节、线条和色调。
使用尺寸：会缩小到怎样的尺寸，哪些特征在小尺寸下仍需可辨。
输出：需要的清晰度与文件形式；需要独立主体时明确真实透明背景。
```

例如，为出行记录准备一个通勤自行车类别符号，可以要求完整侧视、简化细节、与已选类别图标采用相同线条及配色，在预定单元尺寸下保留车轮和车架辨识度。图像负责识别，记录数量和标签由网页表达。若比较具体车型，应先找对应产品图。

抠图任务则围绕已有对象描述：保留上传图片中的完整主体和识别特征，移除背景，输出真实透明图像；不要把它改写成重新设计产品的提示词。先验证一份结果在页面中的表现，再扩展整组。没有合适生成或编辑工具时，选用已有素材、简单 SVG 或调整构图。

## 在作品中核对素材

选素材时用代表文件核对职责与身份、实际尺寸、主体边界和透明效果。随实现把这些判断并入[同一次实际阅读检查](implementation.md#实现后的检查)：小尺寸可辨；同组视觉分量协调；图片大小不会被误读为数值；缺图记录仍在总体中；运动经过区域没有遮挡、露底或身份线索丢失。已在作品中确认的结果直接沿用，无需另做素材演示页。

实现沿用已确定的素材文件、对象关联和展示约定：例如显示框、锚点、是否有详情版、哪些通道承担量值。预加载、局部图片框、SVG 绘制组与点击详情使用[实现参考](implementation.md#素材单元)的接口。真实照片、档案与生成插画按其性质保留来源说明；素材制作完成与整段叙事成立分别判断。
