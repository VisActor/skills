# 单元可视化数据叙事

**好的作品 = 好的叙事编排 + 好的可视化设计。** 把可追溯记录或有明确单位的量，组织成能观察、比较和回看证据的单元集合。作品的价值来自读者看清的关系；单元的造型、构图和运动可以同时带来主题感与表现力。

## 定位与范围

核心数据表达围绕单元展开。单元可以是圆点、方格、小人、图标、图片卡片或文本片段；坐标、标签、统计参考线、差值标注、文字和素材帮助读者理解它们。必要的趋势、连续量或汇总背景可以用常规折线图、面积图等表达，与单元视图共同服务主问题。

**核心数据叙事先按连续演进的全出血主舞台设计。** 让读者看见已有证据怎样被展开、比较、重组和重新理解，正文随之推进。换指标或图形时，先设计同台承接；开篇、材料细读与收束可按需要置于舞台之外，必要的换场按[选择依据](references/narrative-design.md#先划解释段落再决定舞台)判断。

适用与否由材料和问题决定：保留个体能否解释分布与例外，重新组织能否发现结构，逐份呈现能否让组成或累积更清楚。输入可以是数据表、记录清单、文本档案或研究主题；先整理出可信的记录或汇总量。详情不丰富也可以做单元比较，真实跨期追踪则需要可匹配观测。

精确比较可用共同轴、排序、局部提取和数值标注辅助。由阅读价值决定是否保留单元：不将连续曲线或面积拆成无额外含义的粒子。若整篇问题都依赖汇总趋势、单元没有重要职责，说明更合适的表达范围，而不是为使用本 skill 强行单元化。

默认面向 PC 浏览器，检查实际桌面窗口与笔记本可用高度。没有额外要求时，将精力用于连续阅读，不另做移动端或专门的减弱动态界面。沿用用户已确定的题材、方向、授权与交付条件。

## 作品与设计决定

作品围绕一个主问题展开；章节组织其中一段追问与证据；舞台是让对象和参照在一段解释中持续存在的视觉空间；阅读状态是图文一致、可以停留理解的画面。一段解释可以跨多个状态，多段文字也可以共同解释一幅图，章节与舞台不必一一对应。

全出血描述画面如何使用空间，固定舞台描述图形如何随滚动停留，叙事连续性描述读者的认识如何推进。保持容器不变，并不自动建立认识上的连续。

## 从当前任务进入

两项核心设计以一段完整解释共同推演：**要推进什么认识 → 需要看清哪些数据关系 → 前后构图怎样共同呈现 → 怎样连续展开。** [叙事编排](references/narrative-design.md)决定追问的意义与顺序；[表达与衔接](references/unit-visualization.md#从叙事追问推导表达与衔接)帮助安排这段过程中连续可见的对象、关系和变化。前后构图一起选择，画面显出的新发现也可以改变故事线。[叙事标准](references/narrative-design.md#什么算好的叙事)与[视觉标准](references/unit-visualization.md#什么算好的单元可视化)共同用于设计和评议。

完整创作以叙事与单元表达两页为设计主干；其余指导随素材、样式和实现中的具体决定读取相应小节。文中的构图推导用于理解方法；代码示例与外部作品按具体问题查阅。链接用于定位，不要求递归通读引用文件或运行全部演示。

| 当前任务 | 读取与使用 |
| --- | --- |
| 从主题或材料寻找发现 | 核对[材料与粒度](references/unit-visualization.md#整理材料与确定粒度)，按[选择发现](references/narrative-design.md#从用户关注点选择值得讲的发现)判断意义与证据 |
| 确定故事线、开篇与章节顺序 | 读[叙事编排](references/narrative-design.md)，共同推演认识推进、整体视觉构想与舞台边界 |
| 设计关键画面、编码与运动 | 从[追问与表达的对应](references/unit-visualization.md#从叙事追问推导表达与衔接)选择或组合操作，再细化空间、编码与运动；具体难点参照文中的构图推导和实现链接 |

| 决定是否使用素材、如何呈现与准备 | 读[素材选择与准备](references/material-direction.md)，先判断需要保留的身份与主题特征，再选形式与来源，试用代表素材后再准备整组 |

完整创作按以下过程推进，局部任务从对应环节开始：

1. 理解用户关注点，核对材料的范围、单位、时间与来源，寻找能被证据支持的发现。
2. 选定主问题与读者最终所得，区分主线证据、必要背景与详情。在一份可修订的 `story-design.md` 中连起各段追问和关键画面：本段先让读者认识什么，已有对象或参照怎样帮助下一步比较，结果怎样推进主问题。与[开篇及第一项证据](references/narrative-design.md#开篇与第一项证据一起设计)共同推演，其余段落先记作用与承接；章节和画面数量由解释需要确定。
3. 按设计实现主线，使用真实数据、实际正文与[代表素材](references/material-direction.md#先确定素材承担什么)。**只有尚未确定的构图或连接会影响后续方案时，先在作品内做这段解释。** 例如真实密度能否容纳、换标定后是否仍可比较、几个发现怎样接起来；试作只覆盖这个疑问，成立后直接沿用。不确定性已解决或已有合适实现时，直接推进全篇。基础接线使用[可调用模块](references/implementation.md#可按需取用的模块)，构图、编码和运动由作品决定。
4. 完成来源说明，有值得继续追问的问题时再提供简洁探索。按[合并检查](references/implementation.md#实现后的检查)从开篇连读到收束：读者的认识怎样推进，新的比较怎样接住此前证据，正文强调的关系能否在图中指出。修改后复查受影响段落及前后承接；设计稿只更新影响实现的决定，见[设计记录](references/narrative-design.md#把叙事与画面写进同一份设计稿)。交付作品与已验证范围。

检查合并在实际作品和既有记录中。首稿优先完成可信数据、清楚的主线、可读的关键比较与连贯的结构转场；这些成立后推进全篇，局部措辞、美术和节奏可在后续创作中精修。影响理解的证据缺口或衔接问题当轮修正，不要求每幅图都另试多种方案，也不增加逐步审批。

## 全篇保持的判断

- **有解释意义的状态可以停留，只负责连接的过程自动完成。** 停滚后落到完整画面，正常阅读时也有机会看清证据；动画完成不等于已经提供了阅读时间。
- 讲发展变化时保留可比较的历史；用层级突出当前，密度过高再压缩细节、聚合或并置关键时期。

## 交付与能力边界

研究交付可信数据、来源和候选发现；设计交付可修订的关键状态及连接；实现交付可运行网页、必要数据和素材、启动方式、来源与实际检查记录。各阶段沿用任务要求。

参考中的构图展示推导，代码提供可组合的小机制。按当前问题、数据密度与素材条件取用、改造或另行设计，不把示例选项当作设计范围；有效的方法也无需为求新而更换。作品自行决定美术、布局与运动，可使用合适的外部工具。结构检查和代码测试通过，不等于作品的阅读效果已经成立。
