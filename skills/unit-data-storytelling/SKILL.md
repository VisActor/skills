# 单元可视化数据叙事

**好的作品 = 好的叙事编排 + 好的可视化设计。** 用有明确记录或数量含义的单元，让读者观察、比较和回看证据；造型、构图和运动共同形成主题感与表现力。

## 定位与范围

核心表达围绕圆点、方格、人物符号、图标、图片或文本单元展开，坐标、标注、正文与素材帮助读者理解。必要的趋势、连续量或汇总背景可由折线、面积等常规视图辅助。

**核心数据叙事先按连续演进的全出血主舞台设计。** 让读者看见已有证据怎样被展开、比较、重组和重新理解，正文随之推进。换指标或图形时，先设计同台承接；开篇、材料细读与收束可按需要置于舞台之外，必要的换场按[选择依据](references/narrative-design.md#先划解释段落再决定舞台)判断。

输入可以是数据表、记录清单、文本档案或研究主题。判断保留个体、重新组织或逐份呈现，能否帮助解释分布、例外、结构、组成或累积；详情不丰富也可以做单元比较，真实跨期追踪则需要可匹配观测。

若整篇问题只需汇总趋势，单元没有重要解释职责，应选择更合适的表达；不将曲线或面积拆成无额外含义的粒子。

默认面向 PC 浏览器，检查实际桌面窗口与笔记本可用高度。没有额外要求时，将精力用于连续阅读，不另做移动端或专门的减弱动态界面。沿用用户已确定的题材、方向、授权与交付条件。

## 作品与设计决定

作品围绕一个主问题展开；章节组织其中一段追问与证据；舞台是让对象和参照在一段解释中持续存在的视觉空间；阅读状态是图文一致、可以停留理解的画面。一段解释可以跨多个状态，多段文字也可以共同解释一幅图，章节与舞台不必一一对应。

全出血描述画面如何使用空间，固定舞台描述图形如何随滚动停留，叙事连续性描述读者的认识如何推进。保持容器不变，并不自动建立认识上的连续。

## 从当前任务进入

两项核心设计共同推演：**要推进什么认识 → 数据支持什么关系 → 前后构图怎样呈现 → 怎样连续展开。** [叙事编排](references/narrative-design.md)负责追问与顺序；[单元设计](references/unit-visualization.md)负责表达选择与取舍。画面显出的新发现也可以改变故事线。

完整创作按以下过程推进，局部任务从对应环节开始：

1. 理解用户关注点，核对材料的范围、单位、时间与来源，选择有证据支持的主问题。
2. 在一份可修订的 [story-design.md](references/narrative-design.md#把叙事与画面写进同一份设计稿) 中，按完整解释过程连排关键段的实际正文、图中证据和前后接续。开篇与第一项证据一起设计，其余段落先记作用与依据；章节和状态数量由解释需要决定。
3. 先实现最容易影响全文的关键过程，用真实数据、相邻正文与代表素材，**把关键构图与连接作为完整解释段一同实现**，随即在桌面浏览器观察关系是否可读、图文怎样交接。解决结构问题后扩展其余段落；这段直接属于最终作品，已有可靠实现可沿用，不要求逐屏另做多套试作或等待审批。
4. 完成来源说明，按需提供简洁探索；从开篇到收束进行[合并检查](references/implementation.md#实现后的检查)，修订后复查受影响部分。交付作品、启动方式与实际验证范围。

首稿优先完成可信数据、清楚的主线、可读的关键比较与连贯的结构转场。影响理解的证据缺口或衔接问题当轮修正，局部措辞、美术和节奏可继续精修。

## 全篇保持的判断

- **有解释意义的状态可以停留，只负责连接的过程自动完成。** 停滚后落到完整画面，正常阅读时也有机会看清证据；动画完成不等于已经提供了阅读时间。
- 讲发展变化时保留可比较的历史；用层级突出当前，密度过高再压缩细节、聚合或并置关键时期。

## 交付与能力边界

阶段性交付沿用任务要求：研究提供数据、来源和候选发现；设计提供关键画面及连接；实现提供可运行网页及必要数据、素材和说明。

参考展示推导，代码提供可组合机制；按问题、密度与素材条件取用、改造或另行设计，也可使用合适的外部工具。示例不限定设计范围，有效方法无需为求新而更换。结构检查和代码测试通过，不等于阅读效果成立。
