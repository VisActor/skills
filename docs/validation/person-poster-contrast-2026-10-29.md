## 修复与测量证据

默认 review 现在使用原生 DPR 2 的浏览器上下文，DOM 与 Canvas 同步渲染；对比捕获保留 device 像素。根高宽、实际截图高宽、横纵倍率、裁图原点偏移、声明字体栈及字体加载状态进入报告。Canvas backing store 不足目标倍率时继续报未测量，不能将低分辨率 Canvas 放大当成原生捕获。

分数位置回归发现确定的坐标问题：根宽 1200 CSS px、x=0.25 时，locator 截图包含取整边缘，原生图宽为 2402 px；简单以图宽除根宽会误得 2.001667，且丢失原点偏移。改为公开页面截图 API 的整数文档 clip，显式记录 clip 大小及 root 偏移，分别映射 x/y；根位置或大小在捕获期间变化、捕获被裁切时拒绝测量。两次独立加载也核对根尺寸、必需元素的边界和文字；这不代表对任意页面脚本的完整场景一致性认证。

同一 Mac 原矩阵的测量如下。Mac 1× 本来就通过，没有复现 Linux 未测项。

|项目|原生 1×|原生 2×|
|---|---:|---:|
|“其余”实心像素数|30|236|
|“其余”归一面积（CSS px²）|30|59|
|“已完成”实心像素数|47|340|

|Canvas backing store|548×380|1096×760|

实心字形仍要求黑白通道差至少 230、至少 3 个实际像素，且归一后至少 3 CSS px²；2× 下 11 个像素继续失败，12 个像素达到面积门槛。对比仍采用最差有效背景像素，普通字 4.5:1、大字 3:1。600 CSS px / 12 CSS px 阅读基线不变，原字号 12px 的矩阵图例仍按阅读字号 6px 判失败。

采样不足报告保留 `passed=false`、`unmeasured`，并增加样本数、最大黑白差、面积和原因。仅失败字框生成编号 black/white/clear 裁图，诊断边缘不参与字形采样；拒绝直接诊断目录及目标文件符号链接。声明字体栈不等于已解析出的回退字体。
